# 上限の確認用データを入れる

画面で作った管理者ユーザーに、登録できる上限の数と長さでデータを入れる。
組織を作れる上限の3つ作り、1つ目の組織を、店舗、人、管理者、ポジション、必要人数、募集、希望、メモ、名前の長さまで上限いっぱいにする。
このスキルは、ユーザーが `/seed-max` で起動した場合だけ使う。

入れる中身は`convex/userSeed/maxBuilders.ts`、人向けの説明は`doc/manual/user-seed.md`の「上限の確認用データ」を正本とする。

## 進め方

`.claude/skills/seed/SKILL.md`を読み、その「守ること」と1章から4章までを、そのまま行う。
実行先を聞く、準備を確かめる、ユーザーを選ぶ、削除の確認を取る、の順である。
次の点だけを変える。

- 2章で確かめる`identifier`は、`userSeed/actions.js:seedMaxUserOrganizations`にする。
- 4章で残す組織が1件でもあるときは、上限の数まで組織を作れずに止まる場合があることを伝え、続けるかを聞く。自分で作った組織が残っていると、3つは作れない。
- 5章と6章は、この文書の次の章に置き換える。

## 消して、入れる

```bash
npx convex run userSeed/mutations:resetUserOrganizations '{"userId":"<userId>"}' --deployment <deployment>
npx convex run userSeed/actions:seedMaxUserOrganizations '{"userId":"<userId>"}' --deployment <deployment>
```

- 投入は、組織を作る処理のあと、上限いっぱいの組織の募集を1つずつ、20回に分けて書く。件数が多く、1回では書けないためである。終わるまで待つ。
- 「作成できる組織は3つまでです」のエラーが出たら、残した組織のために上限の数まで作れなかったことを伝えて止める。このときは何も作られていない。
- それ以外のエラーで途中で止まったら、そこまでの分が残っている。原因を直してから、削除の確認を取り直し、`resetUserOrganizations`から入れ直す。投入だけをやり直さない。

## 報告する

投入の結果から、次を短く示す。

- 実行先、ユーザーの名前、消した組織と残した組織。
- 作った3つの組織の名前。1つ目は上限いっぱいの組織で、名前が80文字ある。先頭の「シフトリ上限確認用グループ」で示してよい。
- 上限いっぱいの組織の店舗ごとの募集（期間、状態、提出数、希望の数、メモの数、割り当ての数）。
- `noteMismatchCount`。0でなければ、メモと希望が食い違っていることを不具合として伝える。
- `randomSeed`。同じ内容を作り直したいときは、`seedMaxUserOrganizations`へ`"randomSeed"`を渡す。
- 管理者の招待中の4件は、7日たつと期限切れの扱いになり、管理者の数に数えられなくなること。
- PR環境では、プッシュでpreviewが作り直されるとデータが消えるため、そのたびに`/seed-max`が要ること。
