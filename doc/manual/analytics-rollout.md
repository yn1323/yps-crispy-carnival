# Analytics運用

新しいAnalyticsは、反映後の最初の対象操作、またはJST 03:00の定期処理から自動で計測を始めます。  
PCでの起動、日付指定、backfill、reset、集計用環境変数の切替は日常運用に必要ありません。

この文書は現行コードの運用契約です。対象環境への反映・初回成功を確認した記録ではありません。  
確認済みの環境状態は[リリース状態](release-status.md)だけに記録します。

## 反映時に一度行うこと

| 対象 | 作業 |
|---|---|
| Convex | 新しいschema、計測処理、cron、内部APIを通常のrelease手順で反映する |
| Analytics Worker | 新画面とBFFを既存の配信先へ反映する |
| 初回確認 | 既存URLで本人認証し、店舗一覧、計測開始表示、翌日03:00以降の結果を確認する |

マージとdeploymentは別です。マージしただけで本番へ反映されたとは扱いません。  
Analytics tableには既存データがないという前提で変更しており、データmigrationはありません。要望の新しいflagはoptionalで、既存行の未設定はfalseとして扱います。

Cloudflare Access、配信URL、BFFとConvexの既存credentialは継続利用します。旧集計用環境変数が残っていても、新しい計測開始条件には使用しません。  
この変更のために過去のreset手順を実行しないでください。

## 毎日の使い方

1. いつものAnalytics URLを開いて本人認証する。
2. 「日次」で前日の3指標と推移を確認する。必要なら数値から店舗内訳を開く。
3. 問い合わせ時は「店舗」から店舗・スタッフの現在情報を調べる。要望は「要望」で確認する。

日次はJST 03:00に前日分が集計されます。初日は開始時刻以降だけを数え、途中から計測したことを表示します。  
初回cronまで対象操作がなかった場合は、そのcron時刻から開始します。開始前の日を0件で埋めません。

## 未集計・失敗が表示されたとき

| 表示 | 意味と対応 |
|---|---|
| 計測開始前 | まだ対象操作も初回cronもない。店舗・要望は閲覧可能 |
| 初日は途中から計測 | 正常。翌日以降は完全な一日分になる |
| 未集計・実行中 | 数値は未確定。定期処理と自動復旧の結果を待つ |
| 失敗 | 1分・5分・15分後と翌日の定期処理で再試行。継続する場合は対象日と安全なerror codeから調査する |
| 保持期限切れ | 復旧に必要な入力が25か月を過ぎた。過去の数値を推定で埋めない |

手動backfillを通常の復旧手順にしません。修正が必要な失敗はコードを修正し、保存済みの事実から自動復旧させます。  
集計障害があっても、成功済みの日次と店舗・スタッフ・要望の閲覧は続けられます。

旧方式の手順は[廃止済みreset手順](../archive/manual/2026-08-08_analytics-reset-rollout.md)に履歴として残しています。
