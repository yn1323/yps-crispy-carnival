# エージェント指示体系の再構成計画

## 目的

エージェント向けの指示を、設計原則、常設制約、作業手順へ分け、重複と適用範囲の曖昧さをなくす。
新しいルールが増えたときも、同じ配置基準で正本を選べる状態にする。

## 対象

- `doc/rules/`、`doc/features/`、`doc/manual/`、`doc/INDEX.md`
- ルートと対象範囲別の `AGENTS.md`
- リポジトリ内の `.agents/skills/`
- Claude互換入口と `.claude/skills/` のリンク

## 対象外

- アプリケーションコード、schema、workflow、package設定の変更
- リポジトリ内Skillのグローバル化
- 完了済み計画文書の一括修正

コードと設定を現在事実として扱い、説明が食い違う場合は文書側を直す。

## 配置基準

| 配置 | 移行後の役割 |
|---|---|
| `doc/rules/` | 何を、なぜ守るか |
| `AGENTS.md` | どこで、何を必ず守るか |
| Skill | いつ使い、どう進めるか |
| `doc/features/` | 現在の機能とコード上の入口 |
| `doc/manual/` | 人間が行う運用手順 |
| コード、設定 | 実行可能な現在事実 |

詳細な追加判断は `doc/rules/agent-instructions.md` を正本とする。

## 移行

| 現状 | 対応 |
|---|---|
| `doc/claude/soul.md` にある製品原則 | `doc/rules/ui-design.md` へ移し、旧ファイルを削除する |
| `AGENTS.md` にある設計理由と長い手順 | 対応するRuleまたはSkillへ移し、常設制約と参照だけを残す |
| Skillにある常設の設計原則 | 対応するRuleへ移し、Skillは発動条件と手順へ絞る |
| HowToの執筆手順 | `write-help-content` へ分離する |
| CI/CDの人間向け手順 | `doc/manual/ci-cd.md` へ分離する |
| 重複するConvex導入Skillと互換Skill | 固有内容を正本へ移した後に削除する |
| `.claude/skills/` の一括リンク | `.agents/skills/` 内の各Skillへの個別リンクへ替える |

## 最終構成

### Rule、AGENTS、互換入口

- `doc/rules/`は4文書から6文書へ増やす。配置方針とUI設計を追加し、旧`doc/claude/soul.md`を廃止する。
- `AGENTS.md`は9ファイルから8ファイルへ減らす。`src/routes/AGENTS.md`の内容はフロントエンドRuleとHowTo Skillへ移す。
- 残す各`AGENTS.md`と同じディレクトリに、`@AGENTS.md`だけを読む`CLAUDE.md`を8ファイル置く。
- `.claude/skills`の一括リンクをやめ、採用する17 Skillへの個別相対シンボリックリンクを置く。

### Skillの数と種類

最終的に17 Skillを採用する。
分類ごとに目的が異なり、通常作業の入口が重複しないため、この数を妥当と判断する。

| 分類 | 数 | Skill |
|---|---:|---|
| Convex | 4 | `convex-create-component`、`convex-design-review`、`convex-migration-helper`、`convex-performance-audit` |
| セキュリティ・テスト | 2 | `shiftori-security-review`、`test-strategy` |
| 文章・コンテンツ・UI・画像 | 8 | `cognitive-rhythm-writing`、`convert-images-to-webp`、`demo-ux`、`generate-image`、`japanese-tech-writing`、`seo-article-writer`、`ui-architect`、`write-help-content` |
| Git・レビュー運用 | 3 | `commit`、`create-pr`、`difit-review` |

`seo-article-writer`と`write-help-content`は、前者が検索意図とArticleSite、後者が操作完了とHowToSiteを成果基準にするため分ける。
`demo-ux`は通常画面ではなく、体験型デモの開始、進行、reset、完了、計測を扱うため`ui-architect`と分ける。

新規追加は`write-help-content`だけとする。
次の5 Skillは削除する。

| 削除対象 | 理由 |
|---|---|
| `convex` | 汎用routerであり、具体的な4 Skillと発動範囲が重なる |
| `convex-quickstart` | 既存プロジェクトでは導入手順を使わず、開発サーバー運用とも衝突する |
| `convex-setup-auth` | プロジェクト固有のセキュリティ審査経路を迂回する |
| `shiftori-coding` | `AGENTS.md`と各Ruleへ責務を移したため重複する |
| `write-shiftori-ui-text` | `ui-architect`、`write-help-content`、文章Skillで代替できる |

空の`integration-react-tanstack-router-file-based`ディレクトリも削除する。
採用Skillから参照されない`demo-ux`、`seo-article-writer`、`ui-architect`配下のreference 17ファイルは、現行コード、Rule、Skill本文との重複を避けるため削除する。
外部Skillの登録がなくなるため、残った3件の旧登録と`skills-lock.json`も削除する。

## 実装順序

1. 役割と移行先を台帳化する。
2. Rule、feature文書、manualへ正本を作る。
3. Skillを統合し、危険な既定動作と重複を除く。
4. ルートと下位の `AGENTS.md` を適用範囲別に短くする。
5. Claude互換入口とSkillの個別リンクを作る。
6. サイズ、metadata、リンク、Skill構造、差分を検証する。

移行元は、移行先を作って内容を確認した後に削除する。

## 公式資料との整合

- [OpenAI: Harness engineering](https://openai.com/index/harness-engineering/)に合わせ、`AGENTS.md`は大きな説明書ではなく、適用範囲、常設制約、正本への入口へ絞る。
- [OpenAI: Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)で説明される指示連鎖の既定上限を踏まえ、適用される`AGENTS.md`の合計を計測する。
- [Agent Skills specification](https://agentskills.io/specification)に合わせ、Skillは発動条件をdescriptionへ、手順と参照を本文へ置き、段階的に情報を開示する。
- [Claude Code: How Claude looks up memories](https://code.claude.com/docs/en/memory)に合わせ、各`CLAUDE.md`は同じディレクトリの`AGENTS.md`をimportする互換入口にする。

## 現在の実施状態

Rule、AGENTS、Skill本文、Claude互換入口、17本の個別Skillリンク、文書索引の再構成は完了している。
旧Skill 5件、空ディレクトリ1件、未参照reference 17件、`skills-lock.json`の削除だけは、対象の明示承認後に実施する。

## 検証

- 変更対象が文書、エージェント指示、Skill、symlinkだけであることを確認する。
- ルートから各対象までの `AGENTS.md` 合計が32,768 byte未満、目標24,576 byte以下であることを確認する。
- Skillの `name` と `description` の合計が目標6,000文字以下であることを確認する。
- 全Skillのfrontmatter、参照先、`agents/openai.yaml` を検証する。
- `.claude/skills/` の各リンクが `.agents/skills/` 内の有効なSkillを指すことを確認する。
- 削除予定ファイルの固有内容が正本へ移ったことを差分で確認する。
- Markdownリンク切れ、矛盾、同じ指示の重複を検索する。
