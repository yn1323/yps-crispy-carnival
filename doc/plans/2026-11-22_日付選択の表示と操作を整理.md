# 日付選択の表示と操作を整理 実装計画

> 状態: Active（実装とローカルの検証が完了。依頼者の画面での確認待ち）  
> 作成日: 2026-11-22  
> 対象ブランチ: `feat/1116`

シフト表の「日付選択」の表を、PCとスマートフォンの両方で作り直す。  
対象は「シンプル」と「くわしく」の両方である。  
セルの見た目と操作は[パターン選択の表示と操作を整理](2026-11-22_パターン選択の表示と操作を整理.md)と同じ決まりにし、部品を共通にする。

## 1. 目的

今の表は割り当てのないセルも枠付きの「×」で埋まり、「○」のセルは濃い緑で強すぎる。  
「希望」列は日付の列と同じ情報を持ち、「連絡事項」列は名前と日付の間で日付の列を右へ押している。  
「くわしく」は「入れるもの」で選んでから塗る方式で、見出しには「2/5」「2/3 ▲1」のように数字と記号が多い。  
希望と割り当てを同じセルに重ね、色をポジションと状態だけに使う表にする。

## 2. 範囲

| 対象 | 内容 |
|---|---|
| PCの週の表 | 列の並び、セル、日付の見出し、週の見出し、ポジションのメニュー |
| スマートフォンの日別 | カードから線で区切るリストへ作り直し、充足の行、ポジションのモーダル |
| 休憩 | 日付選択では、休憩を扱わない |

次は範囲に入れない。

- 自動作成の処理
- PCの左の週の一覧のバッジ
- 未提出の案内
- スマートフォンの一覧

## 3. 調査で分かったこと

依頼にあった7項目の順に書く。

1. **表の構成**：PCは`pc/DateOnlyView/`の週の表、スマートフォンは`sp/DateOnlyDailyView/`の1日ずつのカードである。  「シンプル」と「くわしく」は同じ部品の中の分岐で、別の部品ではない。  パターン選択と共通なのは、日付の列、表示設定、その日のテンプレートのメニュー、人数を数える処理である。  セル、ポジションのメニュー、充足の文字はパターン選択の側だけにあった。
2. **セルのデータ**：画面は「スタッフ×日」で1件のデータを持つ。  割り当ては終日の勤務1件で、ポジションを1つ持つ。  希望は「その日を希望した」という有無だけである。  休憩はその日の勤務に、開始と終了の時刻の一覧として付く。
3. **必要人数**：日ごとの必要人数はサーバーが解決して渡す。  日付選択は「ポジションごとの人数」を1日に1組持つ。  人数は`src/domains/shift/staffing.ts`が数え、「2/3 ▲1」の文字は`staffingPresentation.ts`、見出しの合計は`pc/DateOnlyView/StaffingSlotCount.tsx`が作っていた。
4. **PCで緑に塗られた列**：行の並べ替えに使っている日である。  日付の見出しを押すと、その日の「勤務あり、希望あり、休み、未提出」の順に行を並べ替える。  スマートフォンで選んでいる日とは関係がない。
5. **名前横の⚠**：表示中の週の確認事項で、意味は3つある。  「希望のない日の勤務」「未提出のスタッフの勤務」「担当外のポジションの勤務」である。
6. **休憩**：休憩の機能は本番に出ていない（`develop`に休憩の項目がない）。  本番に登録済みの休憩データはない。  ローカル環境にも、日付選択の休憩付きの勤務は1件もなかった（保存済みの勤務3件のうち休憩付きは1件で、時間指定の店舗のもの）。  開発環境は閲覧に確認が要るため見ていない。  日付選択の休憩は表のアイコン、休憩の編集、確定通知の文面、スタッフの確定シフトに使われていた。
7. **スマートフォンの日付の橙のバッジ**：その日の確認事項の件数である。  5のスタッフごとの3種類に加え、「くわしく」では見習いだけの日も数える。  確定を止める誤りがある日は、赤いバッジでその件数を出す。

## 4. 決めたこと

依頼者から「質問があれば、ほかの提出方法を参考に判断して進めてよい」と指示があった。  
次の点は、パターン選択で依頼者が決めた内容に合わせた。

| 点 | 決定 | 合わせた先 |
|---|---|---|
| ⚠の3つの意味 | すべて、割り当てのピルの右上の橙の点にまとめる。理由は点ごとに変える | パターン選択で「点にまとめる」と決めた |
| 割り当てを外す文言 | PCのメニューもスマートフォンのモーダルも「削除」にする | パターン選択で、時間指定のメニューと同じ「削除」に決めた |
| 休憩 | 日付選択でも休憩を扱わない。表示、入力、保存をしない | パターン選択で「休憩そのものを扱わない」と決めた |
| 未提出の人 | たたむまとまりに入れず、通常の行に「未提出」を添えて出す | パターン選択で、名前の横に「未提出」を出すと決めた |
| テストの層 | 操作のテストはStorybookのBehavior Testに置く | パターン選択で、E2Eを既存の契約だけにすると決めた |
| 最後に選んだポジションの置き場所 | 今ある`shiftori:shiftBoard:lastPosition:{shopId}`を、3つの方式で共用する | パターン選択と同じ。依頼文のキー名とは違う |

## 5. 共通の仕様

### 5.1 セルの2つの層

セルは希望を示す点線の輪と、その内側の割り当てのピルで示す。

| 状態 | 見た目 |
|---|---|
| 希望あり・未割り当て | 点線の輪の中に、グレーの文字で「希望」 |
| 希望どおりの割り当て | 点線の輪と、内側の塗りのピル |
| 希望外の割り当て | 塗りのピルだけ。右上に橙の点（8px） |
| 希望も割り当てもなし | 何も描かない。「×」と枠は出さない |

- 輪は幅1.5pxの点線で、角を完全に丸める。
- 輪の位置と大きさは、希望と割り当ての有無で変えない。  希望のないセルも透明な輪の分の余白を取る。
- 期間外の日と定休日は、セルに何も描かず、押せるものも置かない。

### 5.2 点の理由

| 点 | 理由 | 条件 |
|---|---|---|
| 橙 | 希望していない日です | 提出済みの人の、希望のない日への割り当て |
| 橙 | 未提出のスタッフです | 未提出の人への割り当て |
| 橙 | 担当外のポジションです | その人が担当外のポジションでの割り当て |

- 日付選択には時間の重なりがないため、赤い点はない。
- 名前の横の⚠は出さない。
- 理由は、PCでは点にマウスを乗せると出る。  スマートフォンの「くわしく」では、ピルを押して開くモーダルに出す。
- ピルを押してもモーダルが開かない表示（スマートフォンの「シンプル」、ポジションが1つ以下の店舗、閲覧専用）では、点のある日だけ、リストの下に「橙の点：確認が必要」と出す。
- 週の一覧と日付の列のバッジ、確定前の確認の一覧は、これまでと同じ確認事項を数える。

### 5.3 たたむ人

| 画面 | 対象 | 見出し |
|---|---|---|
| PC | その週に希望が1日もなく、割り当ても連絡事項もない人 | 希望なし 2人 |
| スマートフォン | その日の希望も割り当ても連絡事項もない人 | この日の希望がない人 9人 |

- 最初はたたむ。  見出しの横に、名字を3人分まで出し、残りを「ほか1人」とする。
- 開くと通常の行として並び、割り当てができる。  割り当てた人は通常の行へ移り、外すとまとまりへ戻る。
- PCは週を変えるたび、スマートフォンは日付を変えるたびに、たたんだ状態へ戻す。
- 連絡事項の有無は表示設定で隠していても、提出された連絡事項で判定する。
- 未提出の人は「希望がない」と決まっていないため、たたまない。

### 5.4 そのほか

- 仮の勤務は名前の横の「仮」だけで示す。  点線は希望の輪に使うためである。
- スタッフ向けの確定シフトでは希望の輪、点、「未提出」、たたむまとまり、人数と充足を出さない。
- セルのボタンの名前は「名前 日付 勤務あり／勤務なし」のままにする。  「くわしく」でポジションが2つ以上の店舗は、末尾にポジション名を添える。  既存のE2Eがこの名前で探している。

## 6. PCの仕様

### 6.1 表

- 週の表のままにする。  列は「スタッフ → 日付（7日分） → 連絡事項」の順である。
- 「希望」列をなくす。  名前の下の「計◯日」も出さない。
- 「連絡事項」列は右端に置き、残りの横幅をすべて使う。
  - 1件ごとに改行し、先頭に日付を太字で付ける（例：12/1 朝早くから入れます）。  日付順に並べる。
  - 行数を制限せず、全文を出す。  連絡事項の長い人の行だけ高くなる。
  - 連絡事項のない人は空欄にする。  行の高さは40pxである。
  - 募集に連絡事項が1件もない場合と、表示設定で隠した場合は、列の見出しと本文を出さない。  隠した場合は、名前の横のアイコンから読める。
- 連絡事項のある日のセルには、角に小さな三角の印を付ける。
- 見出しの行はスクロールしても上に留める。
- 期間外の日と定休日は、列ごと灰色にする。  見出しに「期間外」「定休日」と出す。
- 並べ替えに使っている日は、列全体を塗らず、見出しの下線と日付の文字の色だけで示す。

### 6.2 シンプル

- ピルの中身は「○」で、色は薄い緑の1色（`teal.100`の地に`teal.800`の文字）である。
- 押すたびに付け外しする。
- 見出しは日付、曜日、人数（8人）を出す。  充足は出さない。

### 6.3 くわしく

- ピルの中身はポジション名で、色はそのポジションの色を薄めた地に、同じ色を濃くした文字である。
- 1つのセルが持つポジションは1つである。
- 「入れるもの」のパレット（ポジションと休憩のチップ）をなくす。  ポジションは押せない凡例として週の見出しの右に出す。
- ポジションが1つ以下の店舗は、「シンプル」と同じ「○」のピルと付け外しにする。

| 操作 | 結果 |
|---|---|
| 空きのセル、「希望」のセルを押す | 最後に選んだポジションで入る。覚えていなければ、ポジションの一覧の先頭で入る |
| 割り当て済みのピルを押す | その場にメニューを開く |

メニューにはポジションの一覧（色の丸と名前、今のポジションにチェック）と区切り線、「削除」を出す。  
開いている間は、数字キーの1〜9でもポジションを選べる。  Escか、メニューの外を押すと、何も変えずに閉じる。

### 6.4 見出しの充足（くわしくだけ）

日付と曜日の下に、ポジションごとの「配置/必要」を縦に並べる。  
形は色の丸と分数（例：● 3/3）で、並びは店舗のポジションの順にそろえる。

| 状態 | 見た目 |
|---|---|
| 足りない | 赤いチップ（地`#F7C1C1`、文字`#791F1F`） |
| ちょうど | グレーの文字 |
| 多い | 紫の文字 |
| 必要人数の指定がない | 配置が1人以上のときだけ、人数を出す |

- 出すポジションは週でそろえる。  その週のどの日にも必要人数がなく、だれも入っていないポジションは出さない。
- 文字を持たないポジションも、同じ高さの空きを残す。  状態が変わっても、分数の位置を動かさないためである。
- 分数の下に、その日のテンプレートの名前を小さく置く。  押すと、その日のテンプレートを選ぶメニューが開く。
- 合計（2/5）と「＋1」「▲1」の表記は出さない。
- ポジションを塗り分けない店舗では、凡例がないため、色の丸を出さない。

週の見出しの横には「充足 41%」を出す。

```text
充足率 = Σ min(配置, 必要) ÷ Σ 必要
```

- 対象はその週の営業日の「日×ポジション」のうち、必要人数のあるすべてである。  多い分は足さない。
- 小数は切り捨てる。  100%未満は赤、100%は緑の文字にする。
- 必要人数の指定が1つもない週は出さない。

週の見出しの右にはポジションの凡例、「必要人数設定」、表示設定を並べる。

## 7. スマートフォンの仕様

- 1日ずつのリストのままにする。  日付の列と橙のバッジは変えない。  「前の日」「次の日」は付けない。
- カードの箱をやめ、線で区切るリストにする。
- 1行は左に名前、右に希望の輪と割り当てのピルを置く。
  - その日の連絡事項は名前の下に吹き出しのアイコンを付けて全文を出す。  表示設定に「連絡事項を表示」は置かない。
  - ピルは高さ28pxで、輪を含めた幅を96pxにそろえる。  押せる範囲は高さ44pxまで広げる。
  - 「希望あり」の文字と⚠は出さない。
- 並びは、その日の連絡事項がある人、希望がある人、希望外で割り当て済みの人、未提出の人の順である。  同じまとまりの中は日付を選んだ時点の並びを保つ。
- 「シンプル」は、ピルが「○」で、押すたびに付け外しする。  日付の見出しの横に人数（3人）を出す。
- 「くわしく」は、ピルがポジション名である。  空きか「希望」を押すと、最後に選んだポジションで入る。
- 「くわしく」で割り当て済みのピルを押すと、画面中央のモーダルを開く。
  - タイトルはスタッフ名、その下に日付を出す。
  - 点の理由がある場合は、日付の下に出す（例：希望していない日です）。
  - ポジションごとの行（高さ48px、今のポジションにチェック）と区切り線、赤い文字の「削除」を出す。
  - 選んだ時点で反映して閉じる。  右上の×か、モーダルの外を押すと、何も変えずに閉じる。
- 「くわしく」は日付の見出しの下に、その日の充足を1行で常に出す。  開閉はなく、入りきらない分は折り返す。
  - 形は「充足 60%　● 販売 2/3　● 製造 1/2」である。  色の決まりはPCと同じである。
  - 凡例がないため、ポジションの名前も文字で出す。
  - 必要人数のない日はこの行を出さず、日付の見出しの横に人数を出す。
- その日のテンプレートのメニューは「くわしく」の日付の見出しの右に置く。  メニューから「必要人数設定」も開ける。

## 8. 休憩をなくす変更

日付選択では休憩を扱わない。

| 場所 | 変更 |
|---|---|
| 画面 | 休憩のアイコン、「入れるもの」の「休憩」、休憩の編集を出さない |
| 読み込み | 保存済みの勤務に休憩が残っていても、画面へ読み込まない |
| 前回の勤務を仮で入れる | 前回の勤務の休憩を引き継がない |
| 保存する勤務 | 画面に休憩が残っていても、保存する勤務に入れない |
| 保存のAPI | 日付選択の募集では、受け取った休憩を保存しない |
| 休憩の決まり | 店舗に決まりがあっても、日付選択のシフト表へ渡さない |

保存済みの休憩を消す処理は足さない。  休憩の残った勤務はその勤務を保存し直した時点で、休憩のない勤務に置き換わる。  
スタッフの確定シフトと確定通知は、保存済みの勤務を読むため、変えない。

## 10. テスト

層は`doc/rules/testing-strategy.md`に従う。

| 層 | 確かめること |
|---|---|
| Logic | セルの状態（希望、割り当て、希望外、未提出、担当外）、期間外の日、定休日、たたむ人の判定 |
| Logic | 充足率（多い分を足さない、切り捨て、必要人数のない日、指定が1つもない週） |
| Logic | 週の表と1日のリストの表示の内容、並び、たたむまとまり、確定シフトの表示 |
| Logic | 状態の操作（最後に選んだポジション、入れ替え、閲覧専用、定休日） |
| Logic | 読み込み、仮の勤務、保存する勤務で休憩を落とすこと |
| Convex Function | 日付選択の募集で、受け取った休憩を保存しないこと |
| Behavior（PC） | 「希望」を押すと「○」が入り、もう一度押すと外れる。希望のない日に入れると橙の点が出る。行の高さと輪の位置が変わらない |
| Behavior（PC） | 空きのセルに最後に選んだポジションが入る。メニューで変えると、その日の見出しの分数と週の充足率が変わる。数字キー、Esc、「削除」 |
| Behavior（PC） | 連絡事項が右端の列に日付付きで出て、その日のセルの角に印がある。隠すと名前の横のアイコンになる |
| Behavior（PC） | 「希望なし」の人が最初はたたまれ、開いて入れると通常の行へ移る |
| Behavior（スマートフォン） | ピルを押して開くモーダルでポジションを変えると、すぐ閉じて反映される。充足の行が変わる。理由と「削除」 |
| Behavior（スマートフォン） | 並びと、「この日の希望がない人」のたたみ、点の意味 |
| E2E | 既存の契約だけを保つ。`E2E-STAFFING-01`は、ポジションをセルのメニューで選ぶ操作に直す |

依頼文はPlaywright E2Eを5本挙げていた。  同じ内容をBehavior Testで確かめ、E2Eは増やさない。  
画面の中だけで完結する操作は、Behavior Testのほうが速く安定して失敗を見つけられるためである。

## 11. 完成条件

1. PCの列が「スタッフ → 日付 → 連絡事項」の順で、「希望」列、「×」、「−」、名前の下の「計◯日」がない。
2. セルが5.1の4つの状態で出て、割り当ての前後で輪の位置と行の高さが変わらない。
3. 名前の横の⚠がなく、5.2の理由が橙の点で出る。
4. 5.3の人がたたまれ、開いて割り当てられる。
5. PCの「くわしく」に「入れるもの」がなく、6.3の操作で割り当てとポジションの変更ができる。
6. PCの日ごとの見出しに6.4の「配置/必要」が出て、合計と「＋1」「▲1」がない。  週の見出しに充足率が出る。
7. スマートフォンが7章のリスト、モーダル、充足の行になっている。
8. 日付選択で休憩の表示、入力、保存がない。
9. 時間指定とパターン選択の表示と操作が変わっていない。
10. `pnpm lint`、`pnpm type-check`、対象のテストが通る。
11. 日付選択の表を通る既存のE2Eが通る。
12. 機能文書と検証契約が今の実装と合っている。

## 12. 依頼文と変えた点

| 依頼文 | 実装 | 理由 |
|---|---|---|
| メニューの「はずす」、モーダルの「シフトからはずす」 | どちらも「削除」 | 4章のとおり、パターン選択と時間指定にそろえた |
| `shiftori:lastPosition:{organizationId}` | `shiftori:shiftBoard:lastPosition:{shopId}` | すでにある置き場所を共用した。ポジションは店舗ごとに違う |
| 登録済みの休憩の扱いは、調査の結果を報告してから決める | 消す処理を足さず、読み込みと保存から外した | 本番にもローカルにも、日付選択の休憩のデータがなかった。8章のとおり |
| Playwright E2Eを5本 | Behavior Test | 10章のとおり |
| 「希望なし」「この日の希望がない人」に、該当する人をまとめる | 未提出の人はまとめない | 4章のとおり |
| スマートフォンのピルは幅52px以上 | 輪を含めて幅96pxにそろえた | ポジション名が入り、右端がそろう |
| スマートフォンのモーダルで、希望外のときに1行出す | 未提出と担当外の理由も同じ場所に出す | ⚠の3つの意味を点にまとめたため |
