# シフト募集の編集仕様

> 文書種別: plan（実装前の合意仕様）  
> 作成日: 2026-09-05  
> 状態: Active（業務仕様合意済み・未実装）

シフト募集を削除して作り直さず、募集期間、定休日、提出期限を変更できるようにする。  
この文書は会話で合意した仕様を記録するものであり、現行実装や実環境への反映を示さない。

## 編集対象と条件

編集対象は、既存募集の開始日・終了日、その募集の定休日、提出期限とする。  
募集のIDは維持し、定休日の変更はその募集に適用する。

| 条件 | 編集可否 |
|---|---|
| 未確定、シフト開始前、提出期限前のすべてを満たす | 編集可能 |
| 確定済み、シフト開始済み、提出期限後のいずれかに該当する | 編集不可 |
| 提出期限後に、提出期限を延長しようとする | 編集不可 |

編集可否は変更前の募集条件で判断する。  
日付・時刻はJSTを使い、既存仕様と同じく提出期限日の23:59までを受付期間とし、翌日0:00以降は期限後とする。

締切までの残り時間による追加制限は設けない。  
残り10分でも編集でき、再提出時間の確保を理由に翌日以降への締切延長を必須にしない。

別の募集との期間重複は許可する。  
重複を理由に編集を禁止せず、重複専用の判定・警告などの特別処理も追加しない。

### 維持する既存の入力制約

日付の妥当性と前後関係は、既存の募集作成時の制約を引き継ぐ。  
開始日は明日以降、終了日は開始日以降、提出期限は今日以降かつ開始日より前とする。

募集期間は両端を含めて最大31日とし、定休日は募集期間内に限定する。  
すべての日を定休日にはできない。

## 提出状態の変更

**勤務対象日**は、募集期間内の日付から、その募集の定休日を除いた日とする。  
変更前と変更後の勤務対象日を比較し、新しく勤務対象になる日が1日でもあれば、対象スタッフ全員を既存の「未提出」に戻す。

新しいステータスは追加しない。  
新しく勤務対象になる日がなければ、提出済み・未提出の状態を維持する。

| 変更例 | 提出状態 |
|---|---|
| 期間延長によって勤務対象日が増える | 全員を未提出に戻す |
| 定休日を削除し、その日が勤務対象になる | 全員を未提出に戻す |
| 提出期限だけを変更する | 維持する |
| 期間を縮小し、勤務対象日の追加がない | 維持する |
| 定休日を追加し、勤務対象日の追加がない | 維持する |
| 期間縮小と定休日削除を同時に行い、変更後に新しい勤務対象日がある | 全員を未提出に戻す |

複数項目を同時に変更する場合も、保存する最終条件で判定する。  
期間全体の長さや操作名ではなく、勤務対象日に追加があるかどうかを基準にする。

## 希望と割当の保持・削除

| 日付の扱い | 希望・割当への処理 |
|---|---|
| 変更後も勤務対象として残る日 | 保存済みの希望・割当を保持する |
| 期間縮小や定休日追加で対象外になる日 | その日の希望・割当を削除する |
| 新しく勤務対象になる日 | 新たな希望入力の対象にする。以前に削除した希望・割当は復活させない |

全員を未提出に戻す場合も、残る日の希望を消さない。  
スタッフは以前の希望が入力済みの状態から確認・再提出できる。

対象外の日のデータは、非表示にするだけでなく削除する。  
期間を縮小してから再拡張する場合や、定休日を追加してから削除する場合も、削除済みの希望・割当を復元しない。

## 変更通知

募集条件を変更したときは、提出済み・未提出に関係なく、対象スタッフ全員へ一律に変更通知を送る。  
勤務対象日の追加、削除、提出期限だけの変更も対象とする。

通知文言は後で決める。

## スタッフへの提出催促

催促時刻は、提出期限の前日17:00 JSTとする。  
変更後の催促予定時刻がまだ未来なら、その時刻の未提出者を対象に催促する。

催促予定時刻を既に過ぎている場合は、追加の催促を行わない。  
変更通知を、提出・再提出の依頼も兼ねる通知として扱う。

| シナリオ | 催促の扱い |
|---|---|
| 締切を短縮し、新しい催促予定時刻がまだ未来 | 新しい時刻へ予約を変更する |
| 締切を短縮し、新しい催促予定時刻を既に過ぎている | 古い予約を無効化し、新たな催促は予約しない。変更通知のみとする |
| 締切を延長し、新しい催促予定時刻がまだ未来 | 新しい時刻へ予約を変更する。以前の催促が送信済みでも再度催促する |
| 締切を変えずに全員を未提出に戻し、催促予定時刻がまだ未来 | 予定どおり、その時刻の未提出者へ催促する |
| 締切を変えずに全員を未提出に戻し、催促予定時刻を既に過ぎている | 新たな催促は予約せず、変更通知のみとする |

締切を変更した場合は、古い予約を無効化する。  
予約時に未提出だった人を固定の送信対象とせず、催促の送信時点で未提出かどうかを確認する。

変更通知から催促までの間隔や、締切までの残り時間による追加のしきい値は設けない。

## 詳細設計で確認する事項

以下は実装方式や画面の詳細を決めるときの確認事項であり、この文書では方式を確定しない。

| 対象 | 確認事項 |
|---|---|
| 画面・文言 | 編集導線、変更内容や削除対象の提示、保存確認、変更通知の文言 |
| 保存・認可 | 対象店舗の管理権限、保存時点の編集可否、募集条件・提出状態・対象外データの整合性 |
| 同時操作 | 他の管理者による編集や、スタッフが古い条件の画面から提出する場合の扱い |
| 通知・予約 | 古い予約、送信待ち通知、再試行による旧条件での誤送信防止。変更と催促時刻が一致する場合の扱い |
| 周辺機能 | 提出状況の集計、シフト表、帳票、提出リンク、締切翌日17時の管理者向け確定催促への影響 |
