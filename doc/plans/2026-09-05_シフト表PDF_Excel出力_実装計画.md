### 実装時の要件判断：Excelの長い勤務区分名

31日分の幅では、正式名称の全文保持と、縮小下限を設けた1区分1表示行を同時に満たせない。Excelの `shrinkToFit` も複数行のセルには適用されない（[Microsoftの仕様](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.alignment?view=openxml-3.0.1)）。  
長文の表示は実装時に調整する方針に基づき、正式名称を保持することを優先し、Excelだけ折り返しに必要な高さへ全スタッフ行をそろえた。これは実装側の暫定判断であり、追加のユーザー承認済みとは扱わない。1スタッフ1物理行と横1ページの印刷設定、時間指定の2行固定、PDF・プレビューの縮小と末尾省略は維持する。31日・30文字・4区分のセルで、元の値、折り返し、行高、Excelの最大行高内に収まることを実ファイルの構造から検証した。表計算ソフトでの実描画と物理印刷は未確認。

| 対象 | 採用する仕様 |
|---|---|
| 導線 | ShiftFormに「PDF・Excel出力」を追加し、出力専用ページを別タブで開く。ページは `src/pages/shift-export/index.tsx` に置く |
| ページ | 共通アプリヘッダー・フッター・ナビゲーションを表示しない。上部はPDF・Excelのダウンロード操作、その下は通常のHTML tableと専用CSSによるプレビュー |
| 表の軸 | 1列目はスタッフ名、2列目以降は募集期間の日付。スタッフ一覧に保存した順番を使う |
| 日付 | `1(火)` 形式。日曜は赤、土曜は青、平日は黒。定休日列のbodyは薄いグレーで全員 `-`。通常日の非出勤も `-` |
| 日付のみ | 出勤日に `○` を表示し、1行固定 |
| 時間指定 | 開始・終了を24時間表示で2行固定。分割勤務があっても行数は増やさない |
| 勤務区分 | PDF・プレビューは1区分につき1行。期間全体の「1人×1日」の最大区分数に全スタッフ行の高さをそろえる。Excelは正式名称の折り返し分も高さへ含める。区分は重複を除き、募集時点の設定順にする |
| 用紙 | A4横。日付は最大31日を横1ページへ均等配置し、スタッフ方向だけ改ページする。店舗名と期間は1ページ目の上部に置く |
| 長文 | PDF・プレビューのスタッフ名は固定幅・1行・末尾省略。勤務区分名は再折り返しせず、下限まで縮小してから末尾省略。Excelの値は正式名称を保持し、スタッフ名は縮小、勤務区分名は縮小と折り返しで表示する |
| 初回対象外 | 直接印刷、共有URL、メール添付送信、CSV、出力設定画面、週・日・ガント等の別レイアウト、Excelからの取り込み |

時間指定の2行に複数区間をどう集約するかは、会話では明示されていない。計画上は「最早の開始・最遅の終了」を暫定案とする。例として `09:00–12:00 / 17:00–21:00` は `09:00` と `21:00` の2行になるため、中抜けは表現できない。「他はいったんそのままでOK」の承認に基づき、この集約方法をMVPへ採用する。4行以上へ自動変更しない。

## データ取得とアクセス境界

`convex/shiftExport/queries.ts` に専用の `getShiftExportData` を追加する。店舗解決には既存の `getShiftBoardShopScopeForOrganization` を利用し、その結果の `shopId` とURLの `expectedOrganizationId`、`recruitmentId` を `managerQuery` へ渡す。  
募集の店舗・組織一致、有効状態をサーバーでも再確認する。現在の編集画面用query全体を流用せず、必要な読み取りだけを構成する。

| 返す情報 | 取得・変換の契約 |
|---|---|
| 店舗・募集 | 店舗名、期間、募集に保存された `submissionPattern`、`shopClosedDates`、保存時刻、確定履歴。現在の店舗設定で過去募集の区分や定休日を再計算しない |
| スタッフ | 現行ボードと同じ、非削除かつシフト対象のスタッフ。過去募集では保存割当のある削除済みスタッフを同一店舗と確認したうえで末尾へ追加する |
| スタッフ順 | 全非削除スタッフを対象に既存scope resolverで完全性を検査し、`ordered` なら店舗entryの保存順で並べてからシフト対象へ絞る。`legacy` なら既存の作成順へ全体を戻し、不完全な保存順を部分採用しない。店舗内の順位の欠番は許容する。削除履歴スタッフは末尾で作成順・IDにより安定させる |
| 保存割当 | 当該募集の保存済み割当だけを返す。時間の正規化は既存の読み取り処理に合わせ、DBを書き換えない。ポジションは帳票へ表示しない |
| 状態 | 確定履歴、通知snapshotとの内容比較、通知処理の要約。通知先、メールアドレス、token、Outbox本文は返さない |
| 上限 | 現行の31日・200スタッフ・2000割当に合わせる。履歴スタッフを含めた件数や取得上限超過を検出し、欠けた表を成功として出さない |

保存履歴も割当もない場合は「保存済みのシフトがありません」と案内し、ダウンロードを止める。全員非出勤として保存済みの募集は、有効な全セル `-` の帳票として出力する。スタッフ0件は空状態にする。期間終了後・編集制限中も、既存の閲覧権限があれば出力可能とする。

保存後にスタッフをシフト対象外へ変更しても、割当が残る場合がある。出力対象外のスタッフに保存割当が残っている場合は、一部の勤務だけを黙って落とした帳票を生成せず、スタッフ設定とシフトの確認を案内して出力を止める。対象外スタッフも帳票へ載せる運用へ変更するかは別の要件判断とし、既存のスタッフ対象条件を暗黙に広げない。

### 確定と通知の表示

| 判定 | 表示方針 |
|---|---|
| 未確定 | 「未確定」を帳票に明示する |
| 確定履歴あり・有効なsnapshotと一致 | 「確定済み」を確定操作の履歴として表示する。全員への通知成功という意味にはしない |
| 確定履歴あり・有効なsnapshotと内容差分あり | 「前回の通知内容から変更あり」を表示する。単なる再保存ではこの表示を出さない |
| snapshot欠落・不正などで比較できない | 確定履歴と「前回の通知内容との比較ができません」を表示する。差分なしへ倒さない |
| 通知の処理中・失敗・確認不能 | 上の内容比較とは独立した補足にする。未完了を「通知済み」にまとめない |

ラベルは暫定で、既存の再通知対象判定と実装時に照合する。比較は `confirmationSnapshots.ts` の正規化と署名検証を再利用する。Outboxを読む既存のprivate helperは、必要な読み取り部分だけを共有し、mutation固有のthrowや再通知予約をqueryへ持ち込まない。元データに差分があっても、名前の省略や時刻の2行化で消える場合があるため、帳票の見た目で通知差分を判定しない。

### Security Lens

| 観点 | 今回守る契約 |
|---|---|
| Actor / Asset | 認証済みの有効な組織管理者が、自組織の対象店舗にあるスタッフ名・勤務予定を出力する |
| Trust boundary / Abuse case | URLのorg、店舗ID、募集IDは利用者が変更できる。他組織・他店舗へのID差し替え、失効した所属、削除対象からの取得を拒否する |
| Server-side enforcement | 既存manager wrapperと募集・店舗の照合、引数・返却validator、上限検査。スタッフ用sessionだけでは利用できない |
| Rate limit / idempotency | 有界のreadだけで、送信・保存・課金処理は行わない。ブラウザ生成は同期ガードで同時実行を抑える。新しいjobや永続dedupeは追加しない |
| Lifecycle / recovery | ログアウト・組織不一致・権限失効・削除が判明したら表示モデルと生成結果を破棄する。生成失敗は同じ操作から再試行できる。保存済みファイルの回収はできない |
| Logs / PII | ファイルをサーバーへアップロードしない。氏名・勤務情報・生成Blobをログや永続ブラウザstorageへ保存しない。Excelの名前・区分名は文字列セルとして扱い、数式や外部リンクへ解釈しない |
| Regression test | Function Testで認証・IDOR・削除・上限・最小DTO、Frontend Unitで生成中断とBlob URLの破棄を検証する |

既存保存形式への変更、新table、migration、backfill、環境変数追加は予定しない。

## 画面と帳票生成

URLは `/shifts/<recruitmentId>/export?org=<organizationId>` とする。出力導線はPC/SP両方に設け、共通ShiftFormには任意の操作slotを渡して管理者用ボードから接続する。スタッフ閲覧画面やデモには追加しない。  
開く直前に既存の `hasUnsavedChanges()` を確認し、未保存なら「変更を保存してから出力してください」と案内する。保存・確定処理中も開かない。自動保存は行わず、保存後の明示操作で別タブを開く。

`bare` は認証・組織scopeの内側で本文だけを表示する。通常表示だけでなくpending、組織読み込み、権限不足、エラー時も共通ヘッダー用余白を取り除く。URL直入力・再読み込み用にCSR shellの動的ルートを登録し、noindexを維持する。

| 責務 | 方針 |
|---|---|
| 共通モデル | `ShiftExport` feature内に配列とplain objectによる `ExportSchedule` を置く。元の正式名称と表示用の行を分け、プレビュー・PDF・Excelの3出力で共用する。検索用Mapは変換関数内だけで使う |
| 寸法 | PDFの有効幅から固定スタッフ列を引き、日数で等分する。行高は全体の表示行数から決め、1ページ目のタイトル領域と後続ページの収容人数を別計算する |
| プレビュー | 白地・細罫線・黒文字を基準とする。SPは操作バーを画面幅に収め、表だけ横スクロール可能にする。画面幅をPDF寸法へ使わない |
| PDF | `@react-pdf/renderer` を遅延読み込みし、明示的に分割したA4横のページを生成する。スタッフ行の途中で分断しない。日付見出しを各ページに繰り返し、ページ番号を付ける |
| 日本語フォント | 再配布・埋め込み可能な静的TTFまたはWOFFをライセンスとともに同梱する。漢字・曜日・丸印・省略記号を実出力で確認する。可変フォントやOS依存フォントだけに頼らない |
| Excel | ExcelJSで1シート、1スタッフ1物理行、セル内改行を使う。同名スタッフを誤結合しない。店舗名・期間・日付見出しを上部へ置き、先頭列と見出しまでの行を固定する |
| Excelの印刷 | A4横、横1ページ、縦自動。`fitToWidth: 1`、`fitToHeight: 0` 相当、印刷範囲、日付見出し行の繰り返しを設定する。PDFとのページ数一致は保証しない |
| 生成・保存 | 押下時の表示モデルを固定して生成する。途中の更新を混ぜず、権限失効などが判明した結果は保存しない。生成中・失敗・再試行をボタン周辺へ表示し、連打を抑止する |

PDFのA4横と明示改ページは[Page API](https://react-pdf.org/docs/v4/components/page)、ブラウザのBlob生成は[On the fly rendering](https://react-pdf.org/docs/v4/advanced/on-the-fly-rendering)、対応フォントは[Fonts](https://react-pdf.org/docs/v4/fonts)で確認した。初期ルートへ生成ライブラリやフォントを読み込まず、対応バージョンは実装開始時に固定する。

ファイル名は `店舗名_シフト表_開始日_終了日` を基本とし、禁止文字と長さを処理する。Excel上での編集がシフトリへ反映されないことを出力ページに短く示す。iOS等で非同期生成後の自動保存が成立しない場合は、生成済みファイルを保存する操作を同じ場所へ表示する。実機未確認を対応済みと扱わない。

## ExcelJSの処理を専用ファイルへまとめる

ExcelJSには列幅・行高、セル内改行、固定行列、A4横、印刷範囲、見出し反復のAPIがある。ライブラリ側の機能追加を先行条件にせず、シフトリ内で31日分の代表帳票を生成してレイアウトを検証する。  
根拠: [ExcelJS公式ドキュメント](https://github.com/exceljs/exceljs#page-setup)。

| ファイル・境界 | 責務 |
|---|---|
| `ShiftExport/excel.ts` | ExcelJSの読み込み、Workbook/Worksheetの生成、セル値・罫線・色・列幅・行高・固定行列・印刷設定、`xlsx.writeBuffer()`とBlob化をまとめる |
| `ShiftExport/script.ts`・`types.ts` | 3形式で共通の帳票データと表示行を作る。ExcelJSの型やWorkbookを持ち込まない |
| 生成hook・View | ダウンロード操作、処理中・失敗・再試行、権限失効時の破棄、Blob URLの作成・解放を担当する。セルやシートを直接操作しない |
| `ShiftExport/excel.test.ts` | 専用ファイルが返した実XLSXの値・寸法・装飾・印刷設定を検証する |

`excel.ts` の呼び出し口は、共通モデルを受け取って `Promise<Blob>` を返す `createShiftExcel(schedule)` を基本とする。呼び出し側へExcelJS固有の型や可変Workbookを公開しない。ExcelJSはこのファイル内で必要時に読み込み、通常のボードやプレビューの初期読み込みへ含めない。

専用ファイル内の処理は意味のあるprivate関数で整理し、汎用Excel基盤や多数のwrapperへ広げない。ファイル保存の直前に生成hookが状態を確認できるよう、`excel.ts` ではブラウザのダウンロード操作を実行しない。PDFとExcelの両形式を使える状態をMVP完了条件とする。

routeの新規ファイル名は既存規則に合わせて `src/routes/_auth/shifts_.$recruitmentId_.export.tsx` とする。pageはroute-wide query・状態分岐・metadataを担当し、ダウンロード処理はfeatureが所有する。帳票固有の整形や寸法を汎用domainへ移さない。自動生成route/API/lockファイルは所定の生成手順で更新する。

## 検証と受入条件

| 契約 | 主担当層 | 代表ケース |
|---|---|---|
| 取得・権限・保存順 | Convex Function | 未認証、有効でない所属、別組織・別店舗、削除募集、保存順とfallback、過去の削除スタッフ、対象外スタッフに残る割当を黙って落とさない、上限超過、不要PIIを返さない |
| 内容比較 | Convex Function | 同内容の再保存、実内容変更、snapshot欠落・不正、隣接区間の意味同値、通知処理中・失敗。既存比較ロジックの単体テストは重複させない |
| 表・改ページ | Logic | 1・7・15・31日、月/年またぎ、1人・各ページ上限・上限+1・200人、3方式、勤務区分最大数、定休日、2行集約、未知optionIdを黙って落とさない |
| 実ファイル | 生成関数のLogic層テスト | PDFの実バイトからA4横・ページ数・日本語・行の欠落/重複を検証。XLSXのセル値・改行・行高・列幅・色・罫線・印刷設定・固定行列・文字列型を解析する。定義オブジェクトだけのassertで完了にしない |
| 画面と生成ライフサイクル | Frontend Unit / Behavior | 未保存時の中止、生成の連打、ライブラリ/フォント取得失敗、再試行、生成中のデータ更新・権限失効、Blob URL解放 |
| 見た目 | Story / VRT | PC/SP、31日、長い氏名・勤務区分名、同名スタッフ、複数区分、全員非出勤、読み込み・空・エラー。PDFは自動生成した合成fixtureの描画も確認する |
| ブラウザ接続 | 少数のE2E | 管理者ボード→別タブ→PDF/XLSXダウンロード、直URLの認証復帰、logout後の再アクセス。表の全組合せや通知配送をE2Eへ重複させない |
| 配信と依存 | build・静的検証 | 新URLのCSR shell、noindex、遅延chunk、フォントasset、初期ボードへの生成ライブラリ混入がないこと |

実装時は対象のLogic・Function・Behaviorを先に実行し、その後 `pnpm lint`、`pnpm type-check`、`pnpm test`、`pnpm build` と必要なVRT・E2Eを行う。既存の開発サーバーを使い、新規起動やAIによる手動ブラウザ操作は追加しない。  
PDFとExcelの印刷結果は利用するビューア・表計算ソフトで差があるため、PDFを固定レイアウトの基準にする。iPhone Safari/Chrome・Android Chromeの保存操作と物理印刷は、自動検証の証拠範囲と実機未確認を区別して引き渡す。
