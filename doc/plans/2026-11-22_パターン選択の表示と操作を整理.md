# パターン選択の表示と操作を整理 実装計画

> 状態: Active（実装とローカルの検証が完了。依頼者の画面での確認待ち）  
> 作成日: 2026-11-22  
> 対象ブランチ: `feat/1116`

シフト表の「パターン選択」の日別表示を、PCとスマートフォンの両方で作り直す。  
対象は「シンプル」と「くわしく」の両方である。

## 1. 目的

今の表は割り当てのないセルも枠付きの「×」で埋まり、割り当て済みのセルが目立たない。  
列の色（早番、遅番、夜番）とポジションの色が重なり、希望と割り当ても離れた列にある。  
希望と割り当てを同じセルに重ね、色をポジションと状態だけに使う表にする。

## 2. 範囲

| 対象 | 内容 |
|---|---|
| PCの日別 | 表の作り直し、日付の見出し、ポジションのメニュー |
| スマートフォンの日別 | カードから表へ作り直し、充足の欄、ポジションのモーダル |
| 休憩 | パターン選択では、休憩を扱わない |

次は範囲に入れない。

- PCとスマートフォンの一覧
- 自動作成の処理
- パターンごとに固定の休憩を持たせる機能

## 3. 調査で分かったこと

- **表の構成**：PCは`pc/ShiftTypeDailyView/`、スマートフォンは`sp/ShiftTypeDailyView/`にある。  どちらも共通の`shiftTypeDailyPresentation.ts`から表示の内容を作る。
- **データ**：画面は「スタッフ×日」で1件のデータを持つ。  その中に、入っているパターンごとの勤務（パターン、ポジション、開始、終了）が並ぶ。  1つのパターンの勤務が持つポジションは1つである。
- **時間の重なり**：違うパターンどうしの重なりは、今も保存と確定を止めていない。  止めているのは、同じパターンを2回入れた場合だけである。
- **名前横の⚠**：「希望していないパターンの勤務」「休み希望の日の勤務」「未提出のスタッフの勤務」「担当外のポジションの勤務」の4つを表す。  時間の重なりは含まない。
- **人数**：数える処理は`src/domains/shift/staffing.ts`、「2/1 ＋1」などの文字は`staffingPresentation.ts`が作る。  どちらも日付選択と共用している。
- **充足率**：時間指定用の`calculateFulfillmentPercent`がある。  パターンを「開始から終了までの区間」として渡せば、同じ関数を使える。
- **休憩**：休憩の機能は本番に出ていない（`develop`に休憩の項目がない）。  本番に登録済みの休憩データはない。
- **休憩の使われ方**：パターン選択の休憩は確定通知の文面、スタッフの確定シフト、PDFの日別、人ごとの合計時間に出る。  「くわしく」で勤務を入れると、店舗の休憩の決まりから休憩が自動で入る。

| 項目 | 決めた内容 |

日付の列の橙の件数と、確定前の確認の一覧は、今の数え方のまま残す。  
時間の重なりはセルの赤い点だけで示し、件数には足さない。

## 5. 共通の仕様

### 5.1 セルの2つの層

| 状態 | 見た目 |
|---|---|
| 希望あり・未割り当て | 点線の輪の中に、グレーの文字で「希望」 |
| 希望どおりの割り当て | 点線の輪と、内側の塗りのピル |
| 希望外の割り当て | 塗りのピルだけ。右上に橙の点 |
| 希望も割り当てもなし | 何も描かない |

- 希望の輪は1.5pxの点線で、角を完全に丸める。
- 割り当ての前後で、輪の位置と大きさを変えない。  希望外のピルにも透明な輪の余白を取る。
- 点は直径8pxでピルの右上に置く。

### 5.2 点の色と理由

| 点 | 理由の文言 | 出す条件 |
|---|---|---|
| 橙 | 希望していないシフトです | 希望のないパターンへの割り当て。休み希望の人への割り当てを含む |
| 橙 | 未提出のスタッフです | 未提出の人への割り当て |
| 橙 | 担当外のポジションです | その人が担当外のポジションでの割り当て |
| 赤 | 夜番と時間が重なっています | 同じ人の、時間が重なる2つのパターンの両方 |

- 橙の理由が2つ重なる場合は、点は1つにし、理由を並べて出す。
- 橙と赤の両方に当たる場合は、赤の点を出し、理由には両方を並べる。
- 時間が隣り合うだけのパターン（15時終わりと15時始まり）は、重なりにしない。
- 日をまたぐパターンは終了を24時より後の時刻（「24:00」など）として比べる。

### 5.3 休み希望の人

- 休み希望で割り当てのない人は、表の下に「休み希望 4人」としてまとめ、最初はたたむ。
- 見出しの横に、名前を3人分まで薄く出し、残りは「ほか1人」とする。
- 開くと通常の行として並び、割り当てができる。
- 割り当てた人は通常の行へ移る。  割り当てを外すと、休み希望のまとまりへ戻る。
- 未提出の人は、休み希望に含めない。

### 5.4 色

- 列ごとの色分けをやめる。  見出しもセルも、背景は無地にする。
- 色を使うのは、ポジション（くわしく）と状態（不足、多い、点）だけである。

### 5.5 そのほか

- **仮の勤務**：セルの点線の枠をやめる。  点線が希望の意味になるためである。  名前の下の「仮」だけで示す。
- **連絡事項**：名前の横の吹き出しアイコンで示す。  PCはマウスを乗せると、スマートフォンはタップすると本文を出す。
- **スタッフ向けの確定シフト**：今と同じく、希望の輪と点を出さず、押しても何も起きない。
- **管理者の閲覧専用**：希望の輪と点は出す。  押しても何も起きない。
- **読み上げの名前**：セルのボタンの名前は今の「名前 パターン名 勤務あり／勤務なし」を保つ。  点の理由は名前に足さず、説明として結び付ける。  既存のE2Eがこの名前でセルを探しているためである。

## 6. PCの仕様

### 6.1 表

- 列は「スタッフ」とパターンの列だけにする。  「希望」列と「連絡事項」列をなくす。
- パターンの列は残りの横幅を等分する。
- 見出しの行はシンプルでもくわしくでも、スクロールしても上に留める。

### 6.2 シンプル

- 見出しはパターン名、時間、人数（今と同じ「3人」）にする。
- ピルの中身は「○」で、全パターン共通の1色にする。
- 空きか「希望」を押すと「○」が入り、「○」を押すと外れる。
- 充足率、必要人数との比較、テンプレートの選択は出さない。

### 6.3 くわしく

- ピルの中身はポジション名で、そのポジションの色の薄い塗りに、濃い文字を載せる。
- 空きか「希望」を押すと、最後に選んだポジションで入る。
- 割り当て済みのピルを押すと、その場にメニューを開く。
  - 中身はポジションの一覧（色の丸、名前、今のポジションにチェック）、区切り線、「削除」である。
  - 開いている間は、数字キーの1〜9でもポジションを選べる。
  - Escか、メニューの外を押すと、何も変えずに閉じる。
- 最後に選んだポジションは、ガントと同じ場所に覚える（localStorageの`shiftori:shiftBoard:lastPosition:{shopId}`）。  覚えていない場合は、店舗の先頭のポジションを使う。
- 日付の見出しの右のポジションのチップは、押せない凡例にする。  「休憩」のチップは出さない。
- ポジションが1つ以下の店舗では、ピルの中身を「○」にし、押すと付け外しする。  選ぶポジションがないため、メニューは出さない。

### 6.4 見出しの充足（くわしくだけ）

- パターン名と時間の下に、ポジションごとの「配置/必要」を1行で並べる。  形は「色の丸＋分数」で、ポジション名は書かない。

| 状態 | 見た目 |
|---|---|
| 足りない | 赤いチップ（背景 `#F7C1C1`、文字 `#791F1F`） |
| ちょうど | グレーの文字 |
| 多い | 紫の文字 |
| 必要人数の指定がない | 配置が1人以上のときだけ、人数を出す（例：● 1） |

- 状態が変わっても、出す位置を変えない。  チップと文字は同じ幅を取る。
- 今の合計（「2/2」）と、「＋1」「▲1」の表記はなくす。
- 見習いだけのパターンに出す注意のアイコンは、分数の右に残す。  日付の列の件数と対応しているためである。
- 日付の見出しの横に、「充足 56%」と、「必要人数」のラベルを付けたテンプレートの選択を置く。
- 充足率は100%未満を赤系の文字、100%を緑の文字にする。

充足率は次の式で求め、小数を切り捨てる。

```text
充足率 = Σ min(配置, 必要) × パターンの長さ ÷ Σ 必要 × パターンの長さ
```

対象は必要人数のある「パターン×ポジション」のすべてである。  多い分は足さない。

## 7. スマートフォンの仕様

- スタッフごとのカードをやめ、PCと同じ「スタッフ」とパターンの列の表にする。
- パターンは最大4つである。  幅375pxで4列が入るよう、スタッフの列を狭め、横スクロールにしない。
- 上の「入れるもの」の行は出さない。  凡例も出さない。  ピルと充足の表にポジション名があるためである。
- 見出しの時間は短い表記（「9–15」）にする。

| 表示 | 内容 |
|---|---|
| シンプル | 見出しは「早番　9–15・3人」。ピルの中身は「○」で、タップで付け外しする |
| くわしく | 日付の見出しの右にテンプレートの選択を置く。その下に「充足 56%」の行を置き、開くと「ポジション×パターン」の表で配置と必要を出す。最初は閉じる |

- 「くわしく」で空きか「希望」をタップすると、最後に選んだポジションで入る。
- 割り当て済みのピルをタップすると、画面中央のモーダルを開く。
  - 見出しはスタッフの名前と「遅番 15:00〜21:00」である。
  - 中身はポジションの一覧（今のポジションにチェック）と「削除」である。
  - 点の理由がある場合は、見出しの下に出す。
- 充足の表の色はPCの見出しの充足と同じにする。

## 8. 休憩をなくす変更

パターン選択の募集では次の4か所から休憩をなくす。  時間指定と日付選択は変えない。

| 場所 | 変更 |
|---|---|
| 画面の表示と入力 | PCとスマートフォンの日別から、休憩の印、休憩のチップ、休憩の編集への入口をなくす |
| 自動で入る休憩 | 「くわしく」で勤務を入れたときに、休憩の決まりから休憩を入れる処理を、パターン選択では動かさない |
| 読み込みと保存 | 画面は、読み込んだ勤務と、前回の勤務を仮で入れた勤務から、休憩を落とす。保存する勤務にも休憩を入れない |
| 保存のAPI | パターン選択の募集では受け取った休憩を保存しない |

- 通知、スタッフの確定シフト、PDFは変えない。  休憩がなければ、何も出ないためである。
- ローカルと開発環境に残っている休憩付きの勤務は、移行しない。  次に保存したときに休憩が外れる。

## 10. テスト

テスト層は`doc/rules/testing-strategy.md`の表に沿って決めた。

| 守ること | 層 | 置き場所 |
|---|---|---|
| セルの状態、点の理由、重なりの境界、休み希望の判定 | Logic | `src/domains/shift/shiftTypeCells.test.ts` |
| パターンの充足率 | Logic | `src/domains/shift/staffingFulfillment.test.ts` |
| ポジションを指定する操作、休憩を保存しない | Logic | `shiftTypeAssignments.test.ts`、`buildAssignments.test.ts` |
| 表示の内容（見出しの分数、休み希望の名前の並び） | Logic | `shiftTypeDailyPresentation.test.ts` |
| 押したあとの表示の変化 | Behavior | PCとスマートフォンの`index.stories.tsx` |
| 見た目 | VRT | 同じStoryのうち、代表の状態（`Board`など） |
| パターン選択の募集で休憩を保存しない | Convex Function | `convex/shiftBoard/mutations.test.ts` |
| 提出から割り当て、確定、閲覧までの接続 | E2E | 既存の`E2E-SHIFT-03`（セルの探し方だけを直す） |

Logicで守る境界は次のとおりである。

- 時間が隣り合うだけのパターン（15時終わりと15時始まり）は、重なりにしない。
- 日をまたぐパターン（翌0:00まで）と、その前のパターンの重なりを判定する。
- 休み希望の人への割り当ては、希望外として扱い、通常の行に出す。
- 未提出の人への割り当てと、担当外のポジションへの割り当ては、それぞれの理由を返す。
- 必要人数が1つもない日は、充足率を返さない。

Behaviorで守る操作は次のとおりである。  PCとスマートフォンの両方で確かめる。

1. シンプル：「希望」を押すと「○」が入り、もう一度押すと外れる。  希望のないセルに入れると橙の点が出る。
2. くわしく：空きのセルを押すと、最後に選んだポジションが入る。  ピルを押し、メニュー（スマートフォンはモーダル）でキッチンに変えると、見出しの分数が変わる。
3. 時間が重なる2つのパターンに入れると、両方に赤い点が出る。
4. 休み希望の人は、最初はたたまれている。  開いて割り当てると、通常の行へ移る。
5. PCのメニューは数字キーでポジションを選べ、Escで何も変えずに閉じる。

実装のあと、PCの幅1280pxと1440px、スマートフォンの幅375pxで画像を撮り、次を確かめる。

- 「×」と列の色がなくなっている。
- 割り当ての前後で、行の高さが変わらない。

| 必要人数が1つもない日 | 充足率だけを出さない。テンプレートの選択は、店舗にテンプレートが1つでもあれば出す |
| スマートフォンの「シンプル」での点の理由 | 点のある日だけ、表の下に点の意味を1行で出す |
| 設定ページの「休憩の決まり」 | 変更なし。設定ページには、もともと休憩の決まりの入力がなかった。シフト表は、パターン選択の店舗に休憩の決まりが残っていても使わない |

実装の中で、次の点を設計から変えた。

- **スマートフォンの凡例**：出さないことにした。  依頼の画像に凡例がなく、ピルと充足の表にポジション名があるためである。
- **表示設定の「連絡事項を表示」**：パターン選択の日別では出さない。  連絡事項を名前の横のアイコンだけで示し、切り替える対象がないためである。
- **スマートフォンのアバター**：出さない。  勤務パターンが4つの店舗でも、名前とポジション名が入る幅を取るためである。
- **人数のまとめの部品**：日付選択のPCも使っていたため、削除せずに`pc/DateOnlyView/`と`staffingPresentation.ts`へ移した。
