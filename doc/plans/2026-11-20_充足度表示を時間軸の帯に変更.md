# 充足度表示を時間軸の帯に変更

作成日: 2026-11-20  
状態: Active（2026-11-20にrepositoryへ実装。対象は時間指定のスマートフォンの「くわしく」表示だけ）

シフト表の日別表示で、必要人数に対する充足の見せ方を変える。  
「ポジション、時間、人数」を縦に並べた一覧をやめ、時間の軸に沿った「充足の帯」と、1日の充足率（%）で示す。

## 1. 対象

今回変えるのは、時間指定の募集の、スマートフォンの「くわしく」表示だけである（2026-11-20、ユーザーの指示）。

| 画面 | 今回 |
|---|---|
| 時間指定のスマートフォンの日別表示（くわしく） | 人数のカードをやめ、充足率の1行と充足の帯に変える |
| 時間指定のPCの日別表示 | 変えない。表の下の帯（「−1」「+2」、赤と青）のまま |
| パターン選択、日付選択のスマートフォン | 変えない。人数のカードのまま |

この間、PCとスマートフォンで、過不足の色と表記が違う。  
PCを同じ帯へそろえる作業は、次の段階に残す。

## 2. 調査結果

### 必要人数の持ち方

時間指定の必要人数は、ポジション、開始、終了を持つバーの配列である。  
同じ時間に重なるバーの本数が、その時間の必要人数になる。  
その日に当たる必要人数は、サーバーが日ごとに解決して画面へ渡す（`ShiftFormStaffingDay.requirements`）。  
テンプレートが当たらない日は `requirements` が `null` になる。

### いまの計算

人数と必要人数の区切りは、`src/domains/shift/staffing.ts` の `buildPositionStaffingBands` が作る。  
区切る時刻は、必要人数のバー、勤務、休憩の開始と終了である。  休憩中の人は数えない。  
充足率（%）の計算は、これまでなかった。

### いまの表示

| 画面 | 表示 |
|---|---|
| スマートフォン | 日付の見出しの下の「人数」のカード。「ポジション → 時間 → 2/3 ▲1」の行を縦に並べる。畳んだ状態は不足の行だけ。カードの右上に「この日のテンプレート」のメニューがある |
| PC | 表の下端に留まる帯。ポジションごとに1行で、時間の軸にそろえる。過不足だけを「−1」「+2」で出す |

### PCの時間の軸

PCの表は、1時間あたりの幅（px）と受付時間から、時刻をpxへ直して置く（`minutesToPixel`）。  
今回の帯は、区間の位置と幅を「帯の範囲に対する割合（%）」で置く。  
PCで使うときは、帯を表の時間の軸と同じ幅の入れ物に置き、範囲に受付時間を渡せば、同じ位置にそろう。

## 3. 仕様

### 帯

- ポジションごとに1本の帯を出す。  必要人数を1つも入れていないポジションの帯は出さない。
- 区間の幅は時間に比例させる。
- 区切る時刻は、人数か必要人数が変わる時刻である。  必要人数の区間だけで区切ると、区間の途中で人数が変わる時間を1色にできないためである。
- 隣り合う区間は、状態と差（人数 − 必要人数）が同じなら1つにつなげる。  0/2と1/3は、どちらも2人不足として1つにする。
- 帯の範囲は、その日の必要人数の、最初の開始から最後の終了までである。  受付時間の外は切り落とす。
- ポジション名は、各帯の上に小さく出す。  ポジションが1つだけの店舗では出さない。
- 区間を押しても何も開かない。

| 状態 | 条件 | 色 |
|---|---|---|
| 不足 | 人数が必要人数より少ない | ピンクに寄せた赤の3段階。1人は薄い、2人は中、3人以上は濃い（文字は白） |
| ちょうど | 人数が必要人数と同じ | 緑 |
| 多い | 人数が必要人数より多い。必要人数が0の時間に人が入っている場合を含む | 紫 |
| 指定なし | 必要人数が0で、だれも入っていない | グレー |

不足の赤をピンクに寄せるのは、ポジションの色に橙を選ぶ店舗が多く、赤と見分けにくいためである。  
多い時間の紫は、ポジションの色の青と橙、警告の色と重ならない色として選んだ。

区間の文字は、不足の区間にだけ、足りない人数（「3」）を出す。  
区間の幅が28px以上のときだけ出し、それより狭い区間は色だけにする。  
警告のアイコンは出さない。  見習いだけの時間も、スマートフォンの帯には出さない（確定の前の確認事項には、これまでどおり出る）。

### 充足率

```
充足率 = Σ min(人数, 必要人数) × 区間の長さ ÷ Σ 必要人数 × 区間の長さ
```

- 全ポジションを合わせて、その日の1つの値にする。
- 多い区間で余った人数は足さない。  ほかの時間の不足を隠さないためである。
- 表示は整数の%で、小数は切り捨てる。  少しでも足りない日は100%にならない。
- 100%未満は不足と同じ系統の赤の文字、100%は緑の文字にする。  アイコンは付けない。
- その日に必要人数が1つもなければ、充足の欄ごと出さない。

### スマートフォンの置き方

- 日付の見出しのすぐ下、スタッフの一覧の上に置く。
- 角丸のカードにせず、画面の幅いっぱいの区画にして、下を細い線で区切る。  上の線は日付の見出しの下の線である。
- 帯は左右の余白なしで端まで伸ばす。  充足率とポジション名には左右の余白を残す。
- 初期状態は閉じている。  閉じた状態は「充足 72%」と細い進捗バーと開閉の矢印の1行で、行の全体を押して開閉する。
- 閉じた1行は、一覧をスクロールしても上端に留める。  開いている間は留めず、一覧と一緒にスクロールする。
- 開閉の状態は、日付を切り替えても保つ。  シフト表を開き直すと閉じた状態に戻る（端末には保存しない）。
- 時間の軸には、3時間ごとの時刻を時だけで出す（「9」「12」）。  24時より後は、PCの時間の軸と同じく「翌3」の形にする。

### 「この日のテンプレート」のメニュー

人数のカードをなくすため、メニューを日付の見出しの右へ移す（2026-11-20、ユーザーの判断）。  PCと同じ位置である。  
必要人数のない日は充足の欄が出ないが、メニューは「未設定」と出るので、スマートフォンからテンプレートを当てられる。

### 残っている判断

日付の一覧のオレンジの件数には、「くわしく」表示のとき、見習いだけの時間帯が1件ずつ足される。  
これは、その日の画面で場所を確かめられることを前提にしていた。  
時間指定のスマートフォンでは、充足の帯に見習いだけの時間を出さなくなったため、件数は出るが、その日の画面では場所を確かめられない。  
件数に足すのをやめるか、帯に出すかは決めていない。

## 4. 範囲外

- 確定のときの不足の警告
- 日付の一覧への不足の表示
- 区間を押したときの詳細の表示
- PCの帯を同じ形へそろえること

## 5. 実装

| 置き場所 | 内容 |
|---|---|
| `src/domains/shift/staffingFulfillment.ts` | 状態の判定、区間の結合、充足率、帯の範囲の純粋関数 |
| `src/components/features/Shift/ShiftForm/fulfillmentPresentation.ts` | 画面へ出す形（色、不足の濃さ、区間の文字、読み上げの文、3時間ごとの時刻） |
| `src/components/features/Shift/ShiftForm/FulfillmentBand.tsx` | ポジション1つ分の帯。PCとスマートフォンで共有する部品 |
| `src/components/features/Shift/ShiftForm/sp/DailyView/FulfillmentSection.tsx` | スマートフォンの充足の区画（開閉の1行、時間の軸、帯の並び） |
| `src/components/features/Shift/ShiftForm/stores.ts` | 選んでいる日の充足（`selectedDayFulfillmentViewAtom`）と、開閉の状態（`isFulfillmentExpandedAtom`） |

帯の部品は、区間の配列、帯の範囲、高さ、文字を出す幅の下限を受け取る。  
区間に出す文字は、画面へ出す形を作る側が決めて渡す。  
PCで「人数/必要」の分数を出すときは、分数の文字を持つ区間を作って同じ部品へ渡す。  この組み立ては、PCを対象にする段階で足す。

区間の文字を幅で出し分ける処理は、CSSのコンテナクエリで行う。  区間の幅をJavaScriptで測らない。

時間指定のスマートフォンの日別表示は、日付の一覧と見出しごと、外側の入れ物でスクロールする。  
充足の区画は、閉じた1行を上端に留めるため、スタッフの一覧の入れ物の中ではなく、日付の見出しと一覧の間に置く。  
一覧の入れ物の中に置くと、その入れ物はスクロールしないため、上端に留まらない（実装計画の照合で見つかり、置き場所を直した）。

時間指定のスマートフォンが使わなくなったため、人数のカード（`StaffingSummary`）から、時間指定の一覧を削った。  
カードは、パターン選択と日付選択のスマートフォンで引き続き使う。
