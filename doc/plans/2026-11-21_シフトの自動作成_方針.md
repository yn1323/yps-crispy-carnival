# シフトの自動作成の方針

作成日: 2026-11-21  
更新日: 2026-11-23（「希望シフトから自動で作成する」の作り方を3章に、その処理で決めることを4章に足した）  
状態: Proposed（「希望シフトから自動で作成する」は[実装計画](2026-11-23_シフトの自動作成_実装計画.md)で実装済み。「AIで作成する」の処理は未着手）

シフト表で、募集期間の勤務をまとめて作る「自動作成」の方針と、決めていない点を残す。  
会話で決めた内容を、処理を作るときに忘れないためのメモである。

## 1. いまの実装

「くわしく」表示で、未確定の募集を編集できるときに、自動作成を開くボタンとメニュー項目を出す。

| 端末 | 置く場所 |
|---|---|
| PC | 上の行の「PDF・Excel」と「下書き保存」の間の「自動作成」ボタン |
| スマートフォン | 上の行の保存と確定のメニューの先頭の「シフトを自動作成」 |

押すと、作り方を選ぶダイアログを開く。  
ダイアログは「希望シフトから自動で作成する」（使用制限なし）と「AIで作成する」（回数制限あり）の2択で、AIを使うときの個人情報の扱いを案内するリンクを置く。  
「作成する」は、いまはダイアログを閉じるだけである。  
期間に勤務がないときに表の上へ出していた案内の帯は、不要とされて外した（2026-11-21）。

## 2. 決めたこと

### 期間をまとめて作る

1日ずつではなく、募集期間の全日をまとめて作る。  
ボタンは、画面全体の操作が並ぶ上の行に置き、日付の見出しには置かない。

AIの費用の試算（2026-11-21、スタッフ22人・8日間、Opus 5.5の料金）では、期間をまとめて1回で作ると約0.40ドル、1日ずつ8回作ると約0.58ドルだった。  
1日だけを作り直す場合は、期間全体の約8分の1になる。  
費用の差は大きくないが、まとめて作るほうが安い。

### ルールとAIをダイアログで選ぶ

作り方は、決まった手順で作るルールと、AIの2つを用意する。  
AIには使える回数の制限を設け、ダイアログで残りの回数を示す。

### 使える条件

自動作成を使えるのは、次の2つを満たすときである。

- 「くわしく」表示であること
- 店舗の設定で、必要人数を入れていること

必要人数はポジションを作らないと入れられないため、ポジションがあることを別の条件として確かめる必要はない。

### 「シンプル」表示には置かない

「シンプル」表示には自動作成を置かない。  
理由は次の3つである。

- 「シンプル」表示は、すでに希望から勤務の候補を作る。必要人数を使わない自動作成は、いまの表示とほぼ同じ結果になる。
- 必要人数に合わせて作ると、結果を確かめるために人数の過不足を見せる必要がある。それは「くわしく」表示の役目で、「シンプル」表示に足すと2つの表示の違いがなくなる。
- 必要人数を入れた店舗は、表示を選んでいなければ「くわしく」で開く。必要人数を使いたい店舗は「くわしく」へ進む流れが、すでにある。

### ポジションを分けない店舗

役割を分けず、人数だけを決めている店舗（全員が何でも担当する小さな店など）も、自動作成を使いたいと考えられる。  
このような店舗が自動作成に求めるのは、必要人数に合わせて希望の中から誰を入れるかを選ぶことであり、ポジションの割り当ては要らない。  
ただし、これは店の形からの推測で、利用データでは確かめていない。

店舗の設定の「ポジションを追加し、時間帯ごとの必要人数を設定する」導線は変えない。  
ポジションを1つ作れば必要人数を入れられ、ポジションが1つの店舗のシフト表は、ポジションの代わりに「勤務」と出すためである。  
「ポジション」という言葉から関係ないと思われて止まるおそれには、案内の文言で対応する（4章）。  
ポジションを作らずに必要人数を入れられるようにするのは、ポジションを作らずに止まっている店舗が多いと分かってからにする。

## 3. 「希望シフトから自動で作成する」の作り方

AIを使わず、決まった手順で作るほうの決めごとを残す。  
2026-11-23の会話で決めた。

### 設定を増やさない

細かい条件を店舗に設定させない。  
代わりに、直近のいくつかのシフトを参考にして組む。

### 希望のない所

希望のない日と時間には、勤務を入れない。  
未提出のスタッフにも入れない。  希望を出さない社員や店長も、ほかのスタッフと同じ扱いにする。  
人が足りない時間は、不足のまま残す。

### 下書きの扱い

作った勤務で、いまの下書きをすべて上書きする。  手で入れた勤務も残さない。  
作った勤務は画面に入れるだけで、保存はしない。  
提出が出そろう前に作る場合の案内は出さない。  未提出の分は作るときに考慮しないためである。

### 希望が通らなかったスタッフ

希望を出した日に勤務が入らなかったスタッフを、作成の結果として持たない。  
シフトを確定したときの通知で、休みとして本人に伝わるためである。

### 1日に複数のポジション、複数のパターン

時間指定では1人の1日の勤務を複数のポジションに分けて作れるようにする。  
パターン選択では1人を同じ日の複数の勤務パターンへ入れられるようにする。

### 休憩

休憩を自動で入れる。  長さは労務の基準の分にする。  
休憩を入れても、その時間帯の人数が必要人数になるように組む。

45分の休憩は、30分単位の必要人数と境目が15分ずれる。  
このずれは、見越して人を多めに入れるか、15分の不足なら許すかで扱う。  使い分けの案は4章に残す。

休憩に労務の基準を使うことは、[必要人数設定](../features/shift-setup.md)の「労務の基準は示さない。休憩の長さや必要人数は、店舗が決めた数字をそのまま持つ」を変える決定である。  
処理を作るときに、この機能文書も直す。

## 4. 決めていないこと

次の点は、「作成する」を押したあとの処理を作るときに決める。

### 希望シフトから作る処理で決めること

3章の決めごとを処理にするときに決める点と、おすすめの案を残す。  
おすすめの案は2026-11-23の会話で出したもので、採否は決まっていない。

#### 役割の分け方

何人要るかは必要人数で、誰が入れるかは希望で決める。  
直近のシフトは迷ったときに誰を選ぶかにだけ使う。  
作った結果には、シフト表の確認事項が1件も出ないようにする。

#### 人が足りないとき

- だれもいない時間を作らないことを、必要人数に届かせることより優先する。
- 不足は1か所に集めず、広げる。
- 希望者の少ない日、時間、ポジションから先に決める。

#### 希望が多いとき

必要人数ちょうどで止め、それより多くは入れない。  
誰を休みにするかは次の順で決める。

1. その人しか入れない所がある人は、そこへ入れる。ほかで代わりがきく人が譲る。
2. 見習いだけの時間帯を作らない。一人前ばかりを選んで見習いが入れなくなることも防ぐ。
3. 「希望のうち入れた割合」を人の間でそろえる。
4. 直近のシフトから分かるその人のいつもの量で補正する。希望を多めに出す人と、絞って出す人を区別するためである。
5. それでも同じなら、前回希望が通らなかった人を優先する。スタッフの並び順では決めない。

勤務時間の合計をそろえる案は採らない。  希望の少ない人に全員を合わせることになるためである。  
複数のポジションを担当できる人は、担当できる人の少ないポジションへ先に入れる。

#### 公平

守るのは、全員を同じ基準で選ぶことと、同じ希望と同じ必要人数なら同じ結果になることである。  
「希望のうち入れた割合」を全員でそろえることは目標にとどめ、保証しない。  
希望のない所へ入れない、必要人数ちょうどで止める、担当外へ入れない、の3つを先に守るためである。  
優先するのは、必要人数を満たす、見習いだけの時間帯を作らない、公平、の順にする。

#### 直近のシフトの使い方

- 直近3回ほどの確定したシフトを、週あたりの量に直して使う。
- 入った量だけでなく、その期間の希望と組にして「希望のうち入った割合」で見る。
- 希望の集め方、ポジション、勤務パターンが変わった期間は使わない。
- 確定したシフトがない店舗と新しく入ったスタッフは、過去なしで同じ手順で作る。
- 連勤や勤務時間の上限は扱わない。希望を出した日は入れてよいものとして作る。

#### 勤務の形

| 項目 | おすすめの案 |
|---|---|
| 時間指定で、希望の時間をどこまで使うか | 必要人数のある時間に合わせて切る。短すぎる勤務と、1日に2回に分かれた勤務は作らない。最短の長さは設定させず、決まった値にする。値は決めていない |
| 複数のポジションに分ける条件 | 1つのポジションで通すと不足が残るときだけ分ける。1つのポジションを続ける長さは1時間以上にする。担当外のポジションへは入れない |
| 複数の勤務パターンへ入れる条件 | 本人が希望したパターンのうち、時間が重ならないものだけにする。1人に2つ入れるのは、ほかの希望者で埋まらないときだけにする |

#### 休憩

| 項目 | おすすめの案 | ほかの案 |
|---|---|---|
| 対象 | 時間指定だけ。パターン選択と日付選択は、いまも休憩を扱っていない | なし |
| 基準の値 | 勤務が6時間を超える場合は45分、8時間を超える場合は1時間を、自動作成の中に決まった値として持つ。店舗の設定は増やさない。店舗に休憩の決まりが残っていて基準より長い場合は、長いほうを使う | 店舗の休憩の決まりを、2段で持てる形に変える。いまの形は「何分以上の勤務に何分」の1段だけである |
| 基準の判定 | 休憩を引いた時間で判定する。条文の基準が労働時間のためである。開始から終了までが6時間を超える勤務は45分、8時間45分を超える勤務は1時間になる。9時から18時の勤務は1時間になる | 開始から終了までの長さで判定する。結果が変わるのは、8時間を超えて8時間45分までの勤務だけで、45分が1時間になる |
| 置く位置 | 勤務の中央に近い時間に置く。人ごとに時刻をずらし、必要人数より人が多い時間を優先する | なし |
| 埋められない休憩 | 希望者が足りないときは、休憩の時間を不足のまま残す。人数を合わせるために休憩を短くしない | なし |
| 45分の休憩の15分のずれ | 休憩中を別の人で埋められる場合は、15分の余りが出ても人を入れる。埋められる人がいない場合は15分までの不足を許し、ほかの勤務を変えてまで埋めない | 人を多めに入れるか、15分の不足を許すかの、どちらか一方だけにする |
| 許した15分の不足の見せ方 | シフト表は人数が変わる時刻で区切るため、いまの表示では15分の不足も不足として出る。出し方を変えるかを決める | いまの表示のままにする |
| 画面と文書での言い方 | 「法律を守れる」とは言わない。自動作成が入れる初期値で、管理者が直せるものとして扱う | なし |

#### そのほか

| 項目 | おすすめの案 |
|---|---|
| ダイアログの説明 | 希望シフトから作るほうの説明から「メモ」を外す。決まった手順ではメモの文章を読めないためである |
| 作る手順 | 埋めにくい所から順に入れ、あとで入れ替えて整える。上限はスタッフ200人、期間31日、勤務2000件で、最適化の専用ライブラリは使わない |
| 守ることの確かめ方 | 確認事項が1件も出ないことを、シフト表の確認事項と同じ判定で確かめる。AIで作るほうも同じ判定を通す |
| 出来の確かめ方 | 過去の希望から作った結果を、管理者が実際に確定したシフトと比べる |
| 複数の店舗に所属するスタッフ | ほかの店舗の勤務との重なりを、いまのシフト表が確かめているかを調べてから決める |

#### 確かめていないこと

- 休憩の基準は条文で確かめた（2026-11-23）。労働基準法第34条第1項は「使用者は、労働時間が六時間を超える場合においては少くとも四十五分、八時間を超える場合においては少くとも一時間の休憩時間を労働時間の途中に与えなければならない。」である。判定に使うのは労働時間で、休憩は労働時間の途中に置く。
- 同じ条の第2項は休憩を一斉に与えると定める。ただし書きと、業種による例外は確かめていない。休憩の時刻を人ごとにずらす作りと関係する。
- 過去の希望は確定のあとも残る（2026-11-23にコードで確かめた）。確定の処理は希望を消さない。希望を消すのは、スタッフの再提出と、募集の勤務対象日を減らす編集だけである。

休憩の表の「基準の判定」は2026-11-23に条文を確かめて書き直した。  
はじめは開始から終了までの長さで判定する案をおすすめにし、9時から18時の勤務は休憩を引いた時間で判定すると45分で足りると書いていた。  
45分の休憩では労働時間が8時間15分になり、8時間を超えるため、この勤務はどちらの判定でも1時間になる。

休憩の長さはこのあとユーザーの指示で、開始から終了までが6時間45分以上の勤務に45分、9時間以上の勤務に1時間と決めた（2026-11-23）。  6時間を少し超える勤務は作らず、6時間に縮める。  店舗の休憩の決まりは使わない。  
上の表の「基準の値」と「基準の判定」は、決める前の案として残す。

処理の作り方は[実装計画](2026-11-23_シフトの自動作成_実装計画.md)に書く。

### これまでの項目

| 項目 | おすすめの案 | ほかの案 |
|---|---|---|
| 必要人数が1日もない店舗 | ボタンとメニュー項目は出したままにする。ダイアログでは「作成する」を押せないようにし、店舗の設定で必要人数を入れると使えることと、設定へのリンクを出す | ボタンとメニュー項目を出さない。ただし、自動作成があることも、必要人数を入れる理由も伝わらない |
| 期間の一部の日にだけ必要人数がない | その日は作らずに飛ばし、ダイアログに「必要人数のない日は作りません」と書く | その日は希望をそのまま勤務にする |
| 店舗の設定で、ポジションがないときの案内 | いまの「ポジションが未設定です。ポジションを追加してください」に、役割を分けない店舗はポジションを1つだけ作れば必要人数を入れられることを足す。文言は2〜3案を出して選ぶ | なし |
| AIの残りの回数 | 回数を数える単位（月ごとなど）と、回数を持つ場所を決める。決まるまで、ダイアログは「回数制限あり」と出す | なし |
| AIの個人情報のヘルプ | ヘルプを作り、ダイアログのリンク先（`aiPrivacyHelpHref`）に渡す | なし |
| ポジションを分けない店舗の数 | ポジションを1つしか使っていない店舗の数を、ローカルか開発環境のデータ、または分析用のデータで確かめる。本番のデータは直接見ない | なし |

AIで作る処理は、[AIシフト下書き機能の詳細設計](2026-07-03_AIシフト下書き機能.md)と[実装仕様書](2026-07-03_AIシフト下書き機能_実装仕様書.md)と関係する。  
この2つは採否が決まっていないため、AIの処理を作る前に、どこまで使うかを決める。
