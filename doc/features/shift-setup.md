# シフト作成の設定

> 文書種別: feature
>
> 最終コード照合: 2026-11-17

店舗が、シフトを組むときに使うポジション、必要人数、スタッフの熟練度を設定する機能である。  
設定した内容は、[シフト表](shift-board.md)の「くわしく」表示で使う。  
何も設定しない店舗は、従来のシフト表をそのまま使える。

## 保証する範囲

設定の保存、店舗をまたいだ参照の拒否、上限の検証を扱う。  
労務の基準は示さない。  休憩の長さや必要人数は、店舗が決めた数字をそのまま持つ。

## 画面

| 画面 | 利用者ができること |
|---|---|
| `/manage/shops/<shopId>/shift-setup?org=<organizationId>` | 店舗のポジション、必要人数、スタッフの熟練度を設定する |

店舗詳細の「シフト作成」と、シフト表の「くわしく」表示にある「シフト作成の設定」から開く。  
URLの`org`と`shopId`の一致は、QueryとMutationの双方で確かめる。  
契約状態によって書き込めない組織では、設定を閲覧だけできる。

## 設定ページの構成

ページは、見出しの行、説明の1文、番号を付けた3つのセクション、保存の行の順に並ぶ。  
幅は、ほかのページと同じコンテンツ幅である。

| 場所 | 表示 | 操作 |
|---|---|---|
| 見出しの行 | 「シフト作成の設定」 | 戻る |
| 1. ポジション | ポジションのバッジ | 「ポジションを編集する」でDialogを開く |
| 2. 必要人数 | テンプレートの一覧と、選んだテンプレートの編集 | テンプレートの追加、並べ替え、名前、使う日、人数、コピー、削除 |
| 3. スタッフのスキル | スタッフとポジションの表 | マスを押してスキルを切り替える、「スキルの役割」を開く |
| 保存の行 | 「保存する」 | 保存する |

番号は、設定する順を表す。  必要人数とスキルはポジションごとに決めるため、ポジションを先に追加する。

ポジションをまだ追加していない店舗では、表示が次のように変わる。

| セクション | ポジションを追加していない店舗 | 追加した店舗 |
|---|---|---|
| 1. ポジション | 「ポジションが未設定です。ポジションを追加してください」と、見出しの右の「ポジションを追加する」 | バッジの一覧と「ポジションを編集する」 |
| 2. 必要人数 | 「ポジションを追加すると、必要人数を設定できます」だけを表示する | テンプレートの一覧と編集 |
| 3. スタッフのスキル | 「ポジションを追加すると、熟練度を設定できます」だけを表示する | スタッフとポジションの表 |

Dialogでポジションを追加して「決定する」を押すと、保存の前から、必要人数とスキルを設定できる。

保存の行はスクロールしても画面の下端に残る。  内容が画面より短いページでも、画面の下端に置く。  
スマートフォンでは下部メニューのすぐ上に残り、「保存する」を幅いっぱいに広げる。  PCでは「保存する」を右に寄せる。  
契約状態によって書き込めない組織では、閲覧専用の案内を表示し、「保存する」を出さない。  編集の操作は押せず、設定した値は読める。

## 設定できる内容

### ポジション

ホールやキッチンなど、勤務の役割を表す。  
名前、色、並び順を変えられ、有効なポジションは10件まで持てる。  並び順は、編集のDialogで行の先頭をつかみ、ドラッグ＆ドロップで変える。  
色は用意した10色から選ぶ。  
用意した10色を入れ替える前に選んだ色（以前の色）は、選び直すまでそのままの色で表示する。  
以前の色のポジションは色を変えずに保存し直せる。  
以前の色は選択肢に出ないため、編集のDialogでは、以前の色のポジションの行はどの色も選んでいない状態で表示する。

ポジションは編集のDialogで一覧を編集する。  
Dialogの「決定する」は編集した一覧をページへ反映するだけで、保存はしない。  保存のしかたは「保存のしかた」を参照する。

店舗を作ったときにできる最初のポジションも、ほかのポジションと同じように名前、色、並び順を変えられ、削除できる。  
Dialogですべてのポジションを削除すると、ポジションを追加していない状態へ戻る。  このとき、それまでの必要人数と熟練度も消える。  
勤務はどれかのポジションに入っている必要があるため、内部では既定のポジションを仮の名前「シフト」へ戻して1件だけ残す。

最初のポジションの名前「シフト」は、ポジションを分けていない店舗の勤務を入れておくための仮の名前である。  画面では、利用者が付けた名前として扱わない。

- 最初のポジションが「シフト」のまま1件だけの店舗は、ポジションをまだ追加していない店舗として扱う。  設定ページには名前を出さず、「ポジションが未設定です。ポジションを追加してください」と「ポジションを追加する」を表示する。  ポジションを追加するまで、必要人数とスタッフのセクションは中身を表示しない。  シフト表では、必要人数を「全体」の人数として表示する。
- 編集のDialogでは、このポジションの名前の欄を空にして出す。
- 2件以上にするときは、「シフト」という名前のポジションを残せない。  スタッフへの通知とシフト表に「シフト」というポジション名が出るのを防ぐためである。  この確認は画面で行う。
- 名前を入れずに1件のまま決定した場合は、分けていない状態のままになる。

勤務と必要人数は、ポジションを名前ではなくIDで持つ。  
ポジションの名前、色、並び順の変更と削除は、確定していないシフトから反映される。  
確定済みのシフトは、確定した時点のポジションのまま表示する。  シフト表、スタッフ向けの表示、確定通知、出力のどれも同じである。  詳細は[シフト表](shift-board.md)を参照する。  
保存済みのポジションの名前を変えたときは、この動きをDialogに表示する。

店舗は「既定のポジション」を1件持つ。  最初は、店舗を作ったときにできるポジションである。  
確定していないシフトでは、ポジションを持たない勤務と、削除したポジションを指す勤務を、シフト表で既定のポジションとして扱う。  
既定のポジションを削除すると、保存した一覧の先頭のポジションが新しい既定になる。

### 必要人数

1日分の必要人数を「テンプレート」として持つ。  
テンプレートには名前を付け、10件まで作れる。  
設定ページでは、必要人数のカードの上にテンプレートを横に並べ、名前と使う日を表示する。  押したテンプレートを、その下で編集する。  
テンプレートごとに、使う曜日と、祝日に使うかどうかを選ぶ。  同じ曜日や祝日は、複数のテンプレートで選べる。  その場合は、並びが先頭のテンプレートをその日に当てる。  テンプレートの並びは、ドラッグで変えられる。  
「指定しない」を押すと、そのテンプレートの曜日をすべて外す。  祝日の選択は変えない。  
曜日も祝日も選ばないテンプレートは、シフト表で日付を選んで当てる。

必要人数の持ち方は、店舗の希望シフトの集め方で決まる。

| 集め方 | 持ち方 |
|---|---|
| 時間指定 | 時間帯ごとの、ポジション別の人数。保存の形はバーで、1本のバーがポジションと開始・終了を持ち、1人分を表す |
| パターン選択 | 勤務パターンごとの、ポジション別の人数 |
| 日付選択 | 1日の、ポジション別の人数 |

時間指定では、人数を30分単位で入れる。  1つの時間に入れられるのは、1ポジションで50人までである。  
保存の形は、1本が1人分のバーである。  ある時刻のポジションの必要人数は、その時刻に重なっているバーの本数になる。  
画面は、読み込むときにバーの重なりを数えて人数へ直し、保存するときに人数をバーへ直す。  
1つのテンプレートで持てるバーは200本までで、人数の変わり目が多すぎるテンプレートは保存できない。  
保存済みのバーと置き方が違っても、時間帯ごとの人数が同じなら、変更として扱わない。

PCでもスマートフォンでも、ポジションごとの時間の帯に、人数を数字で表示する。  同じ人数が続く時間は、1つの区間にまとまる。  
帯の上を横になぞるか、区間を押すと、その範囲の人数を選ぶ欄が開く。  
欄で1人から5人のボタンを押すと、その人数が入る。  6人以上は、ボタンの横の入力欄に数字を入れ、Enterで入れる。  選んだ人数は、その範囲に入っていた人数を置き換える。  欄のゴミ箱のボタンを押すと、その範囲の人数が消える。  
人数の入った区間を押して開いた欄では、開始、終了、人数のどれかを変えた時点で、すぐ帯へ反映する。  時間を変えても欄は開いたままで、続けて直せる。  
時間を伸ばして隣の区間に重なった分は、その区間の人数で置き換わる。  欄を開いたまま縮め直すと、重ねた隣の人数は元に戻る。  
なぞって選んだ範囲、空いた時間、「時間を選んで入れる」から開いた欄では、開始と終了を選び直しても、人数を選ぶまで帯へ入れない。  
「時間を選んで入れる」からは、なぞらずに、開始、終了、人数を選んで入れられる。  
PCでは、ポジション1件を1行で表示し、欄を帯の近くに出す。  
スマートフォンでは、ポジション名の下に帯を画面の幅いっぱいで表示し、欄を帯のすぐ下に出す。  縦に動かした操作はスクロールとして扱う。  
受付時間が長く、1日が幅に収まらない店舗では、帯を横にスクロールする。

パターン選択と日付選択では、人数を数字で入力する。  0人は未設定と同じ意味で、保存しない。

受付時間を短くして範囲の外に出た人数は、消さずに残す。  
設定ページで知らせ、「受付時間に合わせる」で切りそろえるまで、テンプレートを保存できない。  
集め方の種類を変えた店舗では、テンプレートの必要人数を空として表示し、テンプレートの一覧に「再設定」の印を付ける。  
保存済みの以前の必要人数はテンプレートを保存するまで残る。  集め方を元に戻すと、以前の必要人数がそのまま表示される。  
テンプレートを保存すると、すべてのテンプレートがいまの集め方の必要人数で置き換わり、以前の必要人数は消える。  
このため、「再設定」の印が残っている間はテンプレートを保存できない。  「保存する」を押すと、画面は印の付いたテンプレートを開き、保存できない理由を知らせる。  
印はそのテンプレートに必要人数を入れると消える。  必要人数を入れないテンプレートは、削除すれば残りのテンプレートを保存できる。  
テンプレートを変えていない場合は、印が残っていても、ポジションとスタッフのスキルを保存できる。

テンプレートを削除すると、そのテンプレートを当てていた日は祝日と曜日の割り当てへ戻る。  
その日に当たるテンプレートの決まり方と、日ごとの操作は[シフト表](shift-board.md)を参照する。

### 休憩の決まり

設定ページには、休憩の決まりの入力を置いていない。  
保存のAPIと、決まりがある店舗でシフト表に休憩の初期値を入れる動きは残している。

### スタッフ

シフト対象のスタッフごとに、ポジション別の熟練度を持つ。  値は「担当外」「見習い」「一人前」「リーダー」の4つである。  
初期値は、全ポジションで一人前である。  担当できるポジションは1つ以上残す。  
設定ページでは「スタッフのスキル」の見出しで表示する。  
スタッフは、ダッシュボードやシフト表と同じ並び順で表示する。  並び順を使っていない組織では、登録した順になる。  
スタッフとポジションのマスを押すたびに、一人前、見習い、リーダー、担当外の順に値が切り替わる。  担当外の次は一人前へ戻る。  
最後に残った担当できるポジションでは、担当外を飛ばして一人前へ戻る。  ポジションが1件の店舗では、担当外にならない。  
マスには値を言葉で出し、値ごとに地の色を変える。  
PCでは、スタッフを行、ポジションを列にした表を出す。  列の見出しはポジションのバッジで、列に収まらない名前は1行で省略する。  
スマートフォンでは、スタッフごとにポジションのマスを並べる。  
見出しの右の「スキルの役割」を押すと、4つの値の意味を説明するDialogが開く。  閲覧専用でも開ける。

4つの値の意味と、シフト表での働きは次のとおりである。

| 値 | 意味 | シフト表での働き |
|---|---|---|
| 見習い | そのポジションを担当し始めた段階 | 勤務に「見」の印が付く。あるポジションの時間帯が見習いだけになると、確認事項として知らせる |
| 一人前 | そのポジションを1人で担当できる | 印は付かない |
| リーダー | 担当に加えて、突発的なできごとへの対応も任せられる | 勤務に「リ」の印が付く。確認事項には関わらない |
| 担当外 | そのポジションを担当しない | そのポジションに勤務を入れると、確認事項として知らせる。保存と確定は止めない |

シフトを自動で作る機能は、まだない。  Dialogの担当外の説明にある「自動シフト作成時にそのポジションに割り当たることがない」は、その機能を入れたときの働きである。

ポジションの削除で、残ったポジションのすべてが「担当外」になったスタッフは、全ポジションを担当できるものとして扱う。  
熟練度は管理者の画面だけに表示し、スタッフ向けの画面と出力には出さない。

## AIサポート

店の状況を文章で入力すると、テンプレートの下書きが編集中の表に入る。  
下書きは保存されず、管理者が内容を確かめて保存したときに設定になる。

現在は実際のAIにつないでいない。  入力した文章は読まず、店舗の集め方に合う形の必要人数を、ランダムな値で作る。  時間指定では、受付時間いっぱいに1人を置き、昼と夜の時間帯に人数を足す。  
文章は保存せず、ログにも出さない。

Convexの環境変数`SHIFT_SETUP_ASSIST_MODE`が`random`の環境だけで使える。  
未設定の環境では画面に出ず、actionを直接呼んでも下書きを返さない。  
根拠のない人数を店舗へ見せないため、Productionでは設定しない。

## 保存のしかた

ポジション、テンプレート、スタッフの熟練度は、画面の下端にある「保存する」でまとめて保存する。  自動では保存しない。  
「保存する」は、スクロールしても画面の下端に残り、変更がない間は押せない。  
保存していない変更がある状態でページを離れようとすると、確認を表示する。  確認では、保存してから離れるか、保存せずに離れるかを選ぶ。  
編集中の内容を保存せずに捨てる操作は、ページには置いていない。  捨てる場合は、保存せずにページを離れる。

Dialogで反映したポジションの一覧は、保存の前から、必要人数の表とスタッフの表に出る。  
新しく足したポジションにも、保存の前に人数と熟練度を入れられる。  
削除したポジションの人数と熟練度は、編集中の内容から外れる。

保存はポジション、テンプレート、スタッフの熟練度の順に行う。  
新しく足したポジションは、保存するまでIDを持たない。  画面は先にポジションを保存してIDを受け取り、そのIDでテンプレートと熟練度を保存する。  
途中で失敗した場合は、そこまでの分だけが保存される。  もう一度「保存する」を押すと、残りを保存する。  このとき、保存済みのポジションを作り直すことはない。

テンプレートの変更は、確定していないシフト表に反映される。  確定済みのシフト表は、確定した時点の必要人数のまま変わらない。

## Public API

| API | 用途 |
|---|---|
| `api.shiftSetup.queries.getShiftSetup` | 店舗の設定、シフト対象スタッフのポジション別の熟練度、AIサポートを使えるかを返す |
| `api.shiftSetup.mutations.savePositions` | ポジションの一覧を置き換える。一覧にない既存のポジションは論理削除する。既定のポジションを外すと、一覧の先頭を既定にする。保存したポジションのIDを、入力と同じ順で返す |
| `api.shiftSetup.mutations.saveDayTemplates` | テンプレートの一覧を置き換える。既存のテンプレートはIDを引き継ぐ |
| `api.shiftSetup.mutations.saveBreakRule` | 休憩の決まりを保存する。`null`で決まりをなくす。設定ページからは呼ばない |
| `api.shiftSetup.mutations.saveStaffShiftProfiles` | スタッフのポジション別の熟練度をまとめて保存する |
| `api.shiftSetup.mutations.applyDayTemplateToDates` | 未確定の募集の期間内の日付へ、テンプレートをまとめて当てる。`null`でその日だけの指定を消す |
| `api.shiftSetup.mutations.saveDayCustomRequirements` | 未確定の募集の1日に、その日だけの必要人数を保存する |
| `api.shiftSetup.actions.suggestShiftSetup` | テンプレートの下書きを返す。設定は保存しない |

どのAPIも、対象店舗が属する組織の有効な管理者だけが使える。  
受け取ったポジション、スタッフ、テンプレートのIDは、同じ店舗に属することを確かめる。
