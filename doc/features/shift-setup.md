# シフト作成の設定

> 文書種別: feature
>
> 最終コード照合: 2026-11-16

店舗が、シフトを組むときに使うポジション、必要人数、スタッフの熟練度を設定する機能である。  
設定した内容は、[シフト表](shift-board.md)の「くわしく」表示で使う。  
何も設定しない店舗は、従来のシフト表をそのまま使える。

## 保証する範囲

設定の保存、店舗をまたいだ参照の拒否、上限の検証を扱う。  
労務の基準は示さない。  休憩の長さや必要人数は、店舗が決めた数字をそのまま持つ。

## 画面

| 画面 | 利用者ができること |
|---|---|
| `/manage/shops/<shopId>/shift-setup?org=<organizationId>` | 店舗のポジション、必要人数、スタッフの熟練度を設定する |

店舗詳細の「シフト作成」と、シフト表の「くわしく」表示にある「シフト作成の設定」から開く。  
URLの`org`と`shopId`の一致は、QueryとMutationの双方で確かめる。  
契約状態によって書き込めない組織では、設定を閲覧だけできる。

## 設定できる内容

### ポジション

ホールやキッチンなど、勤務の役割を表す。  
名前、色、並び順を変えられ、有効なポジションは10件まで持てる。  
色は用意した10色から選ぶ。

ポジションは編集のDialogで一覧を編集する。  
Dialogの「反映する」は編集した一覧をページへ反映するだけで、保存はしない。  保存のしかたは「保存のしかた」を参照する。

ポジションは1件以上必要で、最後の1件は削除できない。  
店舗を作ったときにできる最初のポジション「シフト」も、ほかのポジションと同じように名前、色、並び順を変えられ、2件以上あれば削除できる。

店舗は「既定のポジション」を1件持つ。  最初は、店舗を作ったときにできるポジションである。  
ポジションを持たない勤務と、削除したポジションを指す勤務は、シフト表と確定通知で既定のポジションとして扱う。  
既定のポジションを削除すると、保存した一覧の先頭のポジションが新しい既定になる。

### 必要人数

1日分の必要人数を「型」として持つ。  
型には名前を付け、20件まで作れる。  
型ごとに、使う曜日と、祝日に使うかどうかを選ぶ。  同じ曜日を2つの型に割り当てることはできず、祝日に使う型も1つだけである。  
曜日も祝日も選ばない型は、シフト表で日付を選んで当てる。

必要人数の持ち方は、店舗の希望シフトの集め方で決まる。

| 集め方 | 持ち方 |
|---|---|
| 時間指定 | バー。1本のバーがポジションと開始・終了を持ち、1人分を表す |
| パターン選択 | 勤務パターンごとの、ポジション別の人数 |
| 日付選択 | 1日の、ポジション別の人数 |

時間指定では、ある時刻のポジションの必要人数は、その時刻に重なっているバーの本数になる。  
バーは30分単位で、1ポジションで同時に重ねられるのは10本、1つの型で持てるのは200本までである。  
バーを足す、伸び縮みさせる、時刻を変える操作のあとは、同じ行で端が接したバーを1本にまとめる。  まとめても、時間帯ごとの必要人数は変わらない。

PCでもスマートフォンでも、バーを表で表示する。  
空いた場所をなぞるとバーが引ける。  PCでは、バーの端をなぞると伸び縮みする。  
画面の行は置き場所で、人を表さない。  置いたバーは、その時間が空いている一番上の行へ寄る。  
「時刻を選んで足す」からは、開始、終了、足す本数を選んで足せる。  足す前に、その時間の必要人数がどう変わるかを表示する。  
バーを押すと、時刻の変更と削除ができる。  
スマートフォンでは、1日を画面の幅に収め、指でなぞってバーを引く。  縦に動かした操作はスクロールとして扱う。  
できあがる必要人数は、時間帯ごとに確かめられる。  PCでは表の下に、スマートフォンではポジションごとのバーのすぐ下に表示する。

パターン選択と日付選択では、人数を数字で入力する。  0人は未設定と同じ意味で、保存しない。

受付時間を短くして範囲の外に出たバーは、消さずに残す。  
設定ページに本数を表示し、「受付時間に合わせる」で切りそろえるまで、型を保存できない。  
集め方の種類を変えた店舗では、型の必要人数を空として表示し、入れ直しが要ることを知らせる。

型を削除すると、その型を当てていた日は祝日と曜日の割り当てへ戻る。  
その日に当たる型の決まり方と、日ごとの操作は[シフト表](shift-board.md)を参照する。

### 休憩の決まり

設定ページには、休憩の決まりの入力を置いていない。  
保存のAPIと、決まりがある店舗でシフト表に休憩の初期値を入れる動きは残している。

### スタッフ

シフト対象のスタッフごとに、ポジション別の熟練度を持つ。  値は「入れない」「新人」「標準」「責任者」の4つである。  
初期値は、全ポジションで標準である。  入れるポジションは1つ以上残す。  
「付ける印」で新人、責任者、入れないのどれかを選び、スタッフとポジションのマスを押して印を付ける。  
印のないマスが標準である。  
同じ印のマスをもう一度押すと標準へ戻り、別の印のマスを押すと選んでいる印に置き換わる。  
最後に残った入れるポジションには「入れない」を付けられず、押すと理由を表示する。  
PCでは、スタッフを行、ポジションを列にした表を出す。  
ポジションの列の見出しから、その列の印をまとめて付けられ、まとめて外せる。  
スマートフォンでは、スタッフごとにポジションのマスを並べ、一覧の上の「まとめて付ける」「まとめて外す」から同じ操作をする。  
まとめて変える対象は、表示しているスタッフである。  
スタッフは名前で絞り込め、絞り込んでいる間は、表示しているスタッフだけが変わる。  
「入れない」をまとめて付けるときは、入れるポジションがなくなるスタッフを変えず、その人数を知らせる。  
ポジションが1件の店舗では、「入れない」の印と、まとめて変える操作を出さない。  
ポジションの削除で、残ったポジションのすべてが「入れない」になったスタッフは、全ポジションに入れるものとして扱う。  
熟練度は管理者の画面だけに表示し、スタッフ向けの画面と出力には出さない。

## AIサポート

店の状況を文章で入力すると、型の下書きが編集中の表に入る。  
下書きは保存されず、管理者が内容を確かめて保存したときに設定になる。

現在は実際のAIにつないでいない。  入力した文章は読まず、店舗の集め方に合う形の必要人数を、ランダムな値で作る。  時間指定では、受付時間いっぱいのバーと、昼と夜の追加のバーを置く。  
文章は保存せず、ログにも出さない。

Convexの環境変数`SHIFT_SETUP_ASSIST_MODE`が`random`の環境だけで使える。  
未設定の環境では画面に出ず、actionを直接呼んでも下書きを返さない。  
根拠のない人数を店舗へ見せないため、Productionでは設定しない。

## 保存のしかた

ポジション、型、スタッフの熟練度は、ページの見出しの右にある「保存する」でまとめて保存する。  自動では保存しない。  
「保存する」は、スクロールしても画面の上端に残り、変更がない間は押せない。  
「元に戻す」は保存していない変更をすべて捨て、最後に保存した内容へ戻す。  
保存していない変更がある状態でページを離れようとすると、確認を表示する。

Dialogで反映したポジションの一覧は、保存の前から、必要人数の表とスタッフの表に出る。  
新しく足したポジションにも、保存の前にバー、人数、熟練度を入れられる。  
削除したポジションのバー、人数、熟練度は、編集中の内容から外れる。  「元に戻す」を押すと、ポジションと一緒に戻る。

保存はポジション、型、スタッフの熟練度の順に行う。  
新しく足したポジションは、保存するまでIDを持たない。  画面は先にポジションを保存してIDを受け取り、そのIDで型と熟練度を保存する。  
途中で失敗した場合は、そこまでの分だけが保存される。  もう一度「保存する」を押すと、残りを保存する。  このとき、保存済みのポジションを作り直すことはない。

型の変更は、確定していないシフト表に反映される。  確定済みのシフト表は、確定した時点の必要人数のまま変わらない。

## Public API

| API | 用途 |
|---|---|
| `api.shiftSetup.queries.getShiftSetup` | 店舗の設定、シフト対象スタッフのポジション別の熟練度、AIサポートを使えるかを返す |
| `api.shiftSetup.mutations.savePositions` | ポジションの一覧を置き換える。一覧にない既存のポジションは論理削除する。既定のポジションを外すと、一覧の先頭を既定にする。保存したポジションのIDを、入力と同じ順で返す |
| `api.shiftSetup.mutations.saveDayTemplates` | 型の一覧を置き換える。既存の型はIDを引き継ぐ |
| `api.shiftSetup.mutations.saveBreakRule` | 休憩の決まりを保存する。`null`で決まりをなくす。設定ページからは呼ばない |
| `api.shiftSetup.mutations.saveStaffShiftProfiles` | スタッフのポジション別の熟練度をまとめて保存する |
| `api.shiftSetup.mutations.applyDayTemplateToDates` | 未確定の募集の期間内の日付へ、型をまとめて当てる。`null`でその日だけの指定を消す |
| `api.shiftSetup.mutations.saveDayCustomRequirements` | 未確定の募集の1日に、その日だけの必要人数を保存する |
| `api.shiftSetup.actions.suggestShiftSetup` | 型の下書きを返す。設定は保存しない |

どのAPIも、対象店舗が属する組織の有効な管理者だけが使える。  
受け取ったポジション、スタッフ、型のIDは、同じ店舗に属することを確かめる。
