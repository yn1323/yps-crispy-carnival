# シフト表

> 文書種別: feature
>
> 最終コード照合: 2026-11-16
>
> 基準commit: `369102c2e70998d8e8bdc561843120a85b224ef8` と出力機能の作業ツリー

シフト担当者がスタッフの希望を見ながら割当を編集し、下書きを保存して、対象期間のシフトを確定する機能である。
募集の作成、一覧、削除は[シフト募集管理](shift-recruitment-management.md)が所有する。

## 保証する範囲

シフト表は、募集方式に対応した割当編集、未保存変更の確認、確定前validation、希望との食い違いの表示、保存と確定、表示中の勤務内容のPDF・Excel出力を扱う。
通知の配送完了は保証せず、確定時に永続的な通知処理を予約するところまでを扱う。

シフト終了日を過ぎた募集は、下書き保存、確定、再通知を受け付けない。
画面だけでなく、mutationも同じ日付条件と募集状態を再確認する。

## 画面と編集方式

| 画面 | 利用者ができること |
|---|---|
| `/shifts/<recruitmentId>/board?org=<organizationId>` | canonicalな組織所属と募集の店舗を照合したうえで、同じシフト表を操作する |
| `/shifts/<recruitmentId>/export?org=<organizationId>` | 管理者が画面から受け取った勤務内容をプレビューし、PDF・Excelをダウンロードする |

シフト表は共通アプリヘッダーとメインナビゲーションを維持し、その下に一覧へ戻る操作と「シフトを調整」の見出しを表示する。  募集状態、提出人数、店舗名は一覧カードで確認し、シフト表ではフォーム直上へ重複表示しない。

日付選択の募集では、PCは週単位の`スタッフ × 日付`表、SPは日別と一覧の切替を使う。
PCの週表は、日付の見出しを押すとその日の希望で行を並べ替える。表の上には左の週タブと同じ期間を表示する。  表の見た目と操作は「日付選択の表」の節に書く。
パターン選択の募集では、スタッフと勤務パターンの組合せを選び、募集作成時点の勤務パターンIDと時間に一致する割当だけを保存する。
時間指定の募集では、希望時間と割当時間を同じ日別画面で比較する。  
SPの日別画面は、スタッフを`出勤あり`、`出勤希望`、`休み`、`未提出`に分ける。  編集中に勤務時間を削除しても、希望時間があるスタッフは`出勤希望`に残し、点線の枠内に希望時間、右上に`勤務なし`を表示する。  閲覧専用ではPC版と同じく希望を表示しないため、勤務がないスタッフは`休み`に分ける。  
日別画面のスタッフは、PCとSPのどちらも、勤務あり、出勤の希望あり、休み、未提出の順に並べる。  勤務ありは勤務の時刻、出勤の希望ありは希望の時刻で、開始と終了が早い順にする。  「くわしく」で開いた直後のように勤務がまだない日も、希望のある人が上に来る。  日付選択は時刻を持たないため、まとまりの中はスタッフの表示順にする。  日付選択のスマートフォンの日別だけは、「日付選択の表」の節の並びにする。

日別の表は3つの提出方法のどれでも、「シンプル」でも「くわしく」でも、希望のない人を下にまとめてたたむ。  
たたむのは、提出済みで、その日の希望も勤務も連絡事項もない人である。  PCの日付選択だけは週の表のため、その週で判定する。  
未提出の人は「希望がない」と決まっていないため、たたまない。  連絡事項のある人も読み落とさないよう、たたまない。

| 提出方法 | 見出し |
|---|---|
| 時間指定 | 休み希望 2人 |
| パターン選択 | 休み希望 2人 |
| 日付選択 | PCは「希望なし 2人」、スマートフォンは「この日の希望がない人 2人」 |

まとまりは最初はたたみ、見出しの横に名字を3人分まで出す。  開くと通常の行（スマートフォンの時間指定はカード）として並び、勤務を入れられる。  
勤務を入れた人は通常の行へ移り、勤務を外すとまとまりへ戻る。  日付（PCの日付選択は週）を変えると、たたんだ状態へ戻す。  
スタッフ向けの確定シフトではたたまずに全員を出す。  
スマートフォンの時間指定はたたむ人を`休み`のまとまりから外し、いちばん下に置く。  `休み`には、連絡事項のある休み希望の人が残る。

募集期間外の日付は確認できても編集できない。
画面幅による操作方法の違いはあるが、保存する割当とserver-side validationは共通である。

時間指定のSP新規追加は「くわしく」表示で選んだポジションを使う。  「シンプル」表示では店舗の実デフォルトポジションを使う。  
時間指定のPC新規ドラッグは、「くわしく」表示では、「入れるもの」で選んでいるポジションを使う。  選ぶ前は、設定のポジションの一覧の先頭を使う。  「シンプル」表示と、ポジションが1つの店舗では、店舗の実デフォルトポジションを使う。  
SPの編集シートは、勤務が0件または1件の日は開始と終了を選ぶ。  「勤務時間を追加」を押すか、勤務が2件以上ある日を開くと、勤務を複数行で編集できる。  行ごとに開始、終了、削除を持ち、重なる時刻は保存しない。  その日の勤務時間をすべて削除する操作は残す。  
「くわしく」表示の複数行の編集では、行ごとにポジションも選ぶ。  ポジションが1つの店舗でも、そのポジションを出す。  ポジションを分けていない店舗では出さない。  
「くわしく」表示では、勤務時間の下で休憩の開始と終了も編集する。  勤務時間が入るまでは休憩の欄を出さない。  「変更する」で勤務時間と休憩をまとめて検証し、どちらかに誤りがあれば保存しない。  休憩の決まりは、別に開く休憩の編集と同じである。

時間指定の画面は、同一スタッフ・同一日・同一実ポジションで完全に隣接する区間だけを一本として読み込む。  正の空白、異なるポジション、日付選択、パターン選択の境界は維持する。  
PCの「シンプル」表示は、ポジションだけが違う隣り合う区間を、続いた1つの勤務時間として扱う。  勤務のバーを押すと続いた勤務をまとめて選び、メニューの削除は、まとめた区間をすべて削除する。  閲覧専用の表示で開く勤務の欄も、続いた1つの勤務時間として出す。  まとめるのは表示と操作の単位だけで、保存する区間は変えない。

期間の表示は、開始日と終了日が同じ年月なら終了日の月を省く（例: `12/23 〜 31`、週タブは`12/21-27`）。  
SPの日付チップは日だけを表示し、定休日や期間外は曜日と同じ行に`火(休)`のように添える。

## スクロールで隠す上の行

シフト表は画面の内側でスクロールする。  内側を下へスクロールすると上の行を隠し、上へ戻すか上端の近くへ来ると表示する。  アプリのヘッダーがページのスクロールで隠れる動きと同じ判定を使う。

| 画面 | 隠す行 | 残す行 |
|---|---|---|
| PC | アプリのヘッダー、シフト表の上の行（戻る、日別と一覧、自動作成、下書き保存、PDF・Excel、確定） | 日付の列、日付の見出し、時刻の行、人数の帯 |
| スマートフォン | アプリのヘッダー、シフト表の上の行（戻る、日別と一覧、保存・確定・出力） | 日付の見出し以下 |

時間指定のスマートフォンの日別表示では、日付の一覧もスクロールで上へ流れ、日付の見出し（◯月◯日、その日のテンプレート、表示設定）が上端に留まる。  充足は、開いているかどうかにかかわらず、その下に留まる。  
日付選択とパターン選択のスマートフォンの日別表示では、日付の一覧も上の行と一緒に隠し、上へ戻すと表示する。  日付の見出しと充足は残る。  
隠している間は、空いた分だけシフト表を画面の上端まで広げる。  
内容が短く、広げるとスクロールできなくなる画面では隠さない。  日付の列や帯の中のスクロールでは隠さない。  選んだ日か、日別と一覧を切り替えると、表示した状態へ戻す。

## シンプルとくわしく

シフト表の情報量は「シンプル」と「くわしく」の2段で切り替える。  
PCとSPのどちらも、日付見出し（PC 日付選択では週の期間の行）の「表示設定」メニューの「シンプル」「くわしく」で切り替える。  一覧には「表示設定」がなく、日別で選んだ表示のまま出す。  
選んだ表示は店舗ごとに保存し、その店舗のシフト表は、最後に選んだ表示で開く。  まだ選んでいない店舗では、ポジションが2つ以上、テンプレート、休憩の決まり、一人前以外の熟練度のどれかがある店舗を「くわしく」で開き、どれもない店舗を「シンプル」で開く。  
下書き保存の前は、「シンプル」表示だけが希望から勤務の候補を作る。  「くわしく」表示は勤務を入れずに開いて希望を点線の枠だけで示し、勤務は管理者が入れる。  候補に店舗の既定のポジションを入れると、全員が同じポジションに見えるためである。  
表示を切り替えると、いま開いている募集の下書きの勤務を、保存済みのものも保存していない編集も削除し、下書き保存の前の状態へ戻す。  表示によって勤務の持ち方（ポジション、休憩）が変わるためである。  ほかの募集の下書きは変えない。  
下書き保存した勤務がある場合だけ、切り替える前に確認を出す。  下書き保存がない場合は、保存していない編集があっても確認せずに切り替える。  
確定済みの募集と、変更できない画面では、切り替えを出さず、店舗に保存した表示のまま表示する。

「シンプル」は従来の画面と同じである。  「くわしく」では、[必要人数設定](shift-setup.md)の内容を使って次を表示する。

| 項目 | 表示 |
|---|---|
| ポジション | ポジションが2つ以上ある店舗で、勤務をポジションの色と名前で示す。パターン選択の日別と日付選択の表は、ポジションの色を薄めたピルにポジション名を書く。時間指定の勤務のバーは、名前を付けたポジションが1つの店舗でも、そのポジションの色にする。この場合、名前は出さない |
| 休憩 | 時刻で入れた休憩を、勤務のバーの内側の斜線、または休憩のアイコンで示す。時間指定のPCの日別表示は、「シンプル」でも勤務のバーに休憩を出し、休憩を入れられる。パターン選択と日付選択は休憩を扱わない |
| 人数と過不足 | ポジションごとの人数。必要人数がある日は、足りない時間と多い時間も示す。  時間指定のスマートフォンは、充足率と、ポジションごとの充足の帯で示す。  削除済みのスタッフに残った勤務は数えない |
| 人ごとの合計 | 時間指定は休憩を引いた勤務時間、パターン選択は勤務時間、日付選択は出勤日数。  管理者の画面だけに表示する。  日別表示（PCの時間指定とパターン選択、スマートフォンの3方式）と、PCの日付選択の週の表には出さず、一覧で確かめる。  日別に出すと、その日の合計に見えるためである |
| 熟練度 | 名前の横にも勤務にも、熟練度の印は出さない。担当外のポジションへ入れた場合は、名前の右の確認事項で知らせる。パターン選択の日別と日付選択の表は、ピルの右上の点で知らせる |
| 仮の勤務 | 「仮」と添える |

### 入れるもの

時間指定のPCの日別表示は、「くわしく」表示の編集中に、これから入れるポジションまたは休憩を、日付の見出しの右の「入れるもの」で選ぶ。  
パターン選択の日別表示と日付選択の表には「入れるもの」を出さない。  ポジションは、セルを押して開くメニュー（スマートフォンはモーダル）で選ぶ。  
時間指定のスマートフォンには「入れるもの」を出さない。  ポジションと休憩は、勤務を押して開く編集シートで選ぶ。  
時間指定のスマートフォンの日別のカードは、勤務のバーの下に、ポジションと休憩をバーと同じ左から右の順に時刻つきで並べる。  ポジションの時間は休憩で区切り、休憩も斜線の四角と「休憩」で1項目にする。  勤務の間の空きも休憩として並べる。  ポジションを塗り分けない店舗では休憩だけを並べる。  
勤務のバーは、その日の最初の左端と最後の右端だけを丸め、勤務と勤務、勤務と休憩の境目には角を付けない。  
一覧は勤務を入れる画面ではないため、「入れるもの」を出さない。  
時間指定のPCの日別表示は、入っている勤務のポジションを、勤務のバーの範囲を選んで変える。  操作は次の「範囲を選んで入れる」に書く。

ポジションを分けていない店舗では、仮の名前「シフト」を選択肢に出さず、「休憩」だけを出す。  
「休憩」は押すたびに選択と解除が切り替わる。  解除している間は、勤務を入れられる。  
仮の名前の扱いは[必要人数設定](shift-setup.md)を参照する。

休憩を選んでいる間は、勤務を押すと休憩の編集を開く。  休憩は開始と終了の時刻で持つ。  画面では件数を制限しない。  保存のAPIは、負荷を防ぐために、1つの勤務につき20件までを受け付ける。  

### 範囲を選んで入れる

時間指定のPCの日別表示は、編集中に、勤務のバーの範囲を選んでからポジションか休憩を入れる。  「シンプル」と「くわしく」で、同じ操作と同じメニューを使う。  
「くわしく」表示では、日付の見出しの右の「入れるもの」で、次に新しく入れるものを選ぶ。  選んでいるものは薄い塗りで示す。  「シンプル」表示には「入れるもの」を出さない。  

| 操作 | 動き |
|---|---|
| 勤務のバーの内側をドラッグ | その時間の範囲を選ぶ。30分単位にそろえ、押したひと続きの勤務の外へは出ない。「入れるもの」で休憩を選んでいる間は、メニューを開かずに、なぞった範囲が15分単位で休憩になる |
| 勤務のバーを押す | 押した区間の全体を選ぶ。区間は、ポジションの境目と休憩で区切る。「シンプル」表示とポジションが1つの店舗では、ポジションの境目で区切らない。休憩を押すと、その休憩を選ぶ |
| 勤務と勤務の間の空きを押す、ドラッグする | 空きは休憩として見せているため、休憩と同じように選ぶ。選べる範囲は、その空きの中だけである。空きが残るのは、スマートフォンで勤務を離して入れた日など、時間指定のPCで変える前の勤務だけである |
| 休憩の開始か終了の近くをドラッグ | 休憩の時間を15分単位で動かす。動かす端は勤務の開始より後、終了より前に収める。反対の端まで動かして15分より短くなる場合は、その休憩を削除する。ほかの休憩と重なった場合は1つにまとめる。短い休憩でも中央を押して選べるよう、端として扱う幅は休憩の幅の3分の1までにする |
| バーの端と、隣り合う区間の境目をドラッグ | 勤務の時間を変える。範囲選択より先に判定する。動かしている間も、休憩はバーに出たままにする |
| 空いている場所をドラッグ | 勤務を新しく入れる。「くわしく」表示では「入れるもの」で選んでいるポジションで入り、休憩を選んでいる間は何も入らない。「シンプル」表示では店舗の実デフォルトポジションで入る |

範囲を選ぶと、その上にメニューが開く。

| 項目 | 選んだときの動き |
|---|---|
| ポジション | 選んだ範囲をそのポジションにする。範囲にかかる休憩は外す。休憩の一部だけがかかる場合は、かかった分だけ外す。区間は必要に応じて分け、隣り合う同じポジションの区間は1つにまとめる。「くわしく」表示で、ポジションが2つ以上の店舗にだけ出す |
| 勤務 | ポジションを出さない表示（「シンプル」表示、ポジションが1つの店舗）で、ポジションの代わりに出す。「勤務」を選ぶと、選んだ範囲にかかる休憩が外れる。勤務と休憩が混ざる範囲でも同じである。「くわしく」表示で、名前を付けたポジションが1つの店舗では、「勤務」の代わりにそのポジションの名前と色を出す。選んだときの動きは「勤務」と同じである |
| 休憩 | 選んだ範囲を休憩にする。ひと続きの勤務の全体か、ポジションの区間の全体を選んでいる間は選べず、項目の下に「まるごと休憩にはできません」と出す |
| 休憩を追加 | 休憩の編集を開く。15分単位の休憩はここから入れる。入っている休憩の時刻の変更と削除も、開いた編集で行う。休憩だけを選んでいる間は、項目の名前が「休憩を変更」になる |
| 削除 | 選んだ範囲にかかる勤務の区間を、区間ごと削除する。ポジションを出さない表示では、選んだ範囲を含む続いた勤務をまとめて削除する。項目の名前は「削除」だけにする |

選んだ範囲がすべて同じポジションなら、そのポジションにチェックが出る。  すべて休憩なら「休憩」にチェックが出る。  
休憩をまたいでポジションを選ぶと、ポジションが変わり、選んだ範囲にかかる休憩が外れる。  休憩だけを選んでポジションを選んでも、その休憩が外れる。  チェックの出ている「休憩」をもう一度選んでも、その休憩が外れる。  
勤務と勤務の間の空きを選んだ場合は、ポジションを選ぶとそのポジションの勤務で埋まり、「勤務」か、チェックの出ている「休憩」を選ぶと、直前の勤務と同じポジションの勤務で埋まる。  
メニューを開いている間は、1〜9のキーで、表示順のポジションを選べる。  
Esc、メニューの外を押す、別のバーの操作を始める、表をスクロールする、のどれかで、何も変えずに閉じる。  
「入れるもの」の横には「バーをなぞると ポジションを変えられます」と出す。  ポジションを分けていない店舗では「バーをなぞると 休憩を入れられます」と出す。  
メニューか、休憩を選んでのなぞりで、ポジションか休憩を一度入れた端末では、この案内を出さない。

「入れるもの」の選択は、次のときに変わる。

| 操作 | 選択 |
|---|---|
| 日付の見出しのポジションを押す | そのポジションになる |
| 勤務のバーのメニューでポジションを選ぶ | そのポジションになる。休憩を選んでいた場合は、休憩の選択が外れる |
| 日付の見出しの「休憩」を押す | 休憩になる |
| 勤務のバーのメニューで「休憩」を選ぶ | 変わらない |

選んだポジションは店舗ごとに端末にも覚え、次にシフト表を開いたときも同じポジションから始める。  
まだ選んでいない端末と、覚えたポジションが削除済みの店舗では、設定のポジションの一覧の先頭から始める。  
休憩の選択は端末に覚えない。  開き直すと、ポジションの選択に戻る。

閲覧専用の表示では、勤務のバーを押すと、勤務の欄が開く。  勤務の欄には、その日の勤務時間と休憩を出す。

### 離れた勤務の間の休憩

時間指定のPCの日別表示は、離れた勤務の間の空きを、休憩の斜線で出す。  持ち方も見た目にそろえる。  
勤務のある日に離れた時間の勤務を入れる、間の区間を削除する、勤務の長さを変える、のどれかで空きができた場合は、次の形に置き換える。

- 空きを、直前の勤務と同じポジションの勤務で埋める。  最初の開始から最後の終了までが、ひと続きの勤務になる。
- 空きだった時間を、時刻で入れた休憩にする。

置き換えたあとは、休憩の編集にもその休憩が出て、保存、通知、出力でも、休憩のある1つの勤務として扱う。  
前から空きのあった日は、時間指定のPCでその日の勤務を変えた時点で、同じ形に置き換える。  表示しただけでは置き換えない。  
休憩の編集の「勤務」の欄は、バーの見た目と同じく、ひと続きの勤務ごとに出す。

### 休憩を入れられる場所

パターン選択と日付選択は休憩を扱わない。  画面に休憩の表示と入力がなく、保存のAPIも、この2つの募集では受け取った休憩を保存しない。  保存済みの勤務に休憩が残っていても、シフト表へ読み込まない。  
時間指定の休憩は、勤務の開始より後、終了より前に入れる。  勤務の頭かお尻にある休憩は勤務ではないため、休憩として扱わない。  
ポジションの違う勤務が隣り合う日は、ひと続きの勤務として扱う。  境目をまたぐ休憩は入れられる。

- 時間指定のPCで勤務の頭かお尻を休憩にした場合は、休憩を入れず、その分だけ勤務を短くする。
- 休憩の編集では、勤務の開始か終了に接する休憩を入力の誤りとして止める。
- 休憩の編集で、時刻の重なる休憩と隣り合う休憩を入れた場合は、いちばん早い開始からいちばん遅い終了までの1つの休憩にまとめて入れる。  重なりを入力の誤りとして止めない。
- 勤務の長さを変えた結果、入れてあった休憩が勤務の頭かお尻にかかった場合は、その休憩を表示、集計、保存に含めない。
- 時間指定のPCで勤務を変えた場合は、勤務の外に出た休憩と、勤務の頭かお尻にかかった休憩を、その時点で取り除く。  勤務を縮めてから伸ばし直しても、取り除いた休憩は戻らない。
- 保存のAPIも、勤務の開始か終了に接する休憩を拒否する。

店舗に休憩の決まりがある場合は、時間指定の「くわしく」表示で、決まりの長さ以上の勤務を新しく作ったときに、休憩の初期値が勤務の中央へ入る。  休憩の前後に勤務が残らない短い勤務と、保存済みの勤務には入れない。  「シンプル」表示では休憩を見せないため、初期値も入れない。

### パターン選択の日別

パターン選択の日別表示はPCもスマートフォンも、列が「スタッフ」と勤務パターンだけの表である。  
「希望」列と「連絡事項」列を持たず、列ごとの色も付けない。  色はポジションと、足りない・多いの状態だけに使う。  
見出しの行はスクロールしても上に留める。

セルは希望を示す点線の輪と、その内側に置く割り当てのピルの2つの層で示す。

| 状態 | 見た目 |
|---|---|
| 希望あり・未割り当て | 点線の輪の中に、グレーの文字で「希望」 |
| 希望どおりの割り当て | 点線の輪と、内側の塗りのピル |
| 希望外の割り当て | 塗りのピルだけ。右上に橙の点 |
| 希望も割り当てもなし | 何も描かない |

輪の位置と大きさは希望と割り当ての有無で変えない。  割り当ての前後で、行の高さも変えない。  
ピルの中身は「シンプル」と、ポジションが1つ以下の店舗では「○」、それ以外の「くわしく」ではポジション名である。

ピルの右上の点は割り当てについて確かめたいことを示す。  名前の横の確認事項のアイコンは出さない。

| 点 | 理由 | 条件 |
|---|---|---|
| 橙 | 希望していないシフトです | 希望のない勤務パターンへの割り当て。休み希望の人への割り当てを含む |
| 橙 | 未提出のスタッフです | 未提出の人への割り当て |
| 橙 | 担当外のポジションです | その人が担当外のポジションでの割り当て |
| 赤 | 夜番と時間が重なっています | 同じ人の、時間が重なる2つの勤務パターンの両方 |

時間が重なる勤務パターンへの割り当ては止めない。  時間が隣り合うだけの勤務パターン（15時終わりと15時始まり）は、重なりにしない。  
理由はPCでは点にマウスを乗せると出る。  スマートフォンの「くわしく」ではピルを押して開くモーダルに出す。  
スマートフォンの「シンプル」では理由を出す場所がないため、点のある日だけ、表の下に点の意味を出す。  
日付の列の件数と、確定前の確認の一覧は、ほかの方式と同じ確認事項を数える。  時間の重なりは数えない。

休み希望（提出済みで、どの勤務パターンも希望していない）で、割り当ても連絡事項もない人は、表の下に「休み希望 4人」としてまとめ、最初はたたむ。  
見出しの横に、名字を3人分まで出し、残りを「ほか1人」とする。  開くと通常の行として並び、割り当てができる。  
割り当てた人は通常の行へ移り、割り当てを外すとまとまりへ戻る。  
未提出の人は通常の行に出し、名前の横（スマートフォンは名前の下）に「未提出」と出す。  
仮の勤務は名前の下の「仮」だけで示す。  点線は希望の輪に使うためである。

操作は次のとおりである。

| 表示 | 空きのセル、「希望」のセル | 割り当て済みのピル |
|---|---|---|
| 「シンプル」、ポジションが1つ以下の店舗 | 押すと「○」が入る | 押すと外れる |
| 「くわしく」（ポジションが2つ以上） | 押すと、最後に選んだポジションで入る | 押すと、PCはその場のメニュー、スマートフォンは画面中央のモーダルを開く |

メニューとモーダルには、ポジションの一覧（今のポジションにチェック）と「削除」を出す。  
PCのメニューは開いている間、数字キーの1〜9でもポジションを選べる。  Escか、メニューの外を押すと、何も変えずに閉じる。  
最後に選んだポジションは時間指定のPCと同じ場所へ、店舗ごとに端末に覚える。  覚えていない場合は、ポジションの一覧の先頭を使う。  
「くわしく」の編集中はPCの日付の見出しの右に、押せないポジションの凡例を出す。

「くわしく」表示ではポジションごとの「配置/必要」を出す。  スタッフ向けの確定シフトには出さない。

| 状態 | 見た目 |
|---|---|
| 足りない | 赤いチップ |
| ちょうど | グレーの文字 |
| 多い | 紫の文字 |
| 必要人数の指定がない | 配置が1人以上のときだけ、人数を出す |

PCは勤務パターンの見出しの名前と時間の下に、色の丸と分数を並べる。  ポジション名は凡例で示す。  
スマートフォンは日付の見出しの下に「充足 56%」の欄を出す。  閉じた状態で始まり、押すと、ポジションの行と勤務パターンの列の表で分数を出す。  
見習いだけのポジションには分数の右に注意のアイコンを添える。  
「シンプル」表示と、スタッフ向けの確定シフトでは、見出しに「3人」の形で人数だけを出す。

充足率は次の式で求め、小数を切り捨てる。  100%未満を赤、100%を緑の文字にする。

```text
充足率 = Σ min(配置, 必要) × 勤務パターンの長さ ÷ Σ 必要 × 勤務パターンの長さ
```

対象は必要人数のある「勤務パターン×ポジション」のすべてである。  多い分は足さない。  
PCは日付の見出しの横に充足率と、「必要人数」のラベルを付けたテンプレートのメニューを出す。  
必要人数が1つもない日は、充足率とスマートフォンの充足の欄を出さない。  テンプレートのメニューは、店舗にテンプレートが1つでもあれば出す。

### 日付選択の表

日付選択の表はパターン選択の日別と同じ決まりで、セルを希望の輪と割り当てのピルの2つの層で示す。  
PCは週の表、スマートフォンは1日ずつのリストである。

PCの週の表は列を「スタッフ → 日付（7日分） → 連絡事項」の順に並べる。  
「希望」列を持たず、名前の下の出勤日数も出さない。  見出しの行はスクロールしても上に留める。  
期間外の日と定休日は列ごと灰色にし、見出しに「期間外」「定休日」と出す。  セルには何も描かない。  
並べ替えに使っている日は列を塗らず、見出しの下線と日付の文字の色だけで示す。  
行の高さは40pxで、連絡事項の長い人の行だけ高くなる。

スマートフォンのリストは線で区切り、1行の左に名前、右に輪とピルを置く。  
その日の連絡事項は名前の下に全文を出す。

| 状態 | 見た目 |
|---|---|
| 希望あり・未割り当て | 点線の輪の中に、グレーの文字で「希望」 |
| 希望どおりの割り当て | 点線の輪と、内側の塗りのピル |
| 希望外の割り当て | 塗りのピルだけ。右上に橙の点 |
| 希望も割り当てもなし | 何も描かない |

輪の位置と大きさは希望と割り当ての有無で変えない。  割り当ての前後で、行の高さも変えない。  
ピルの中身は「シンプル」と、ポジションが1つ以下の店舗では「○」、それ以外の「くわしく」ではポジション名である。

ピルの右上の橙の点は割り当てについて確かめたいことを示す。  名前の横の確認事項のアイコンは出さない。

| 理由 | 条件 |
|---|---|
| 希望していない日です | 提出済みの人の、希望のない日への割り当て |
| 未提出のスタッフです | 未提出の人への割り当て |
| 担当外のポジションです | その人が担当外のポジションでの割り当て |

理由はPCでは点にマウスを乗せると出る。  スマートフォンの「くわしく」ではピルを押して開くモーダルに出す。  
ピルを押してもモーダルが開かない表示（スマートフォンの「シンプル」、ポジションが1つ以下の店舗、閲覧専用）では、点のある日だけ、リストの下に点の意味を出す。  
週の一覧と日付の列の件数、確定前の確認の一覧は、ほかの方式と同じ確認事項を数える。

希望のない人は下にまとめ、最初はたたむ。

| 画面 | まとめる人 | 見出し |
|---|---|---|
| PC | その週に希望が1日もなく、割り当ても連絡事項もない人 | 希望なし 2人 |
| スマートフォン | その日の希望も割り当ても連絡事項もない人 | この日の希望がない人 9人 |

見出しの横に、名字を3人分まで出し、残りを「ほか1人」とする。  開くと通常の行として並び、割り当てができる。  
割り当てた人は通常の行へ移り、割り当てを外すとまとまりへ戻る。  
PCは週を変えるたび、スマートフォンは日付を変えるたびに、たたんだ状態へ戻す。  
未提出の人はまとめず、名前の横に「未提出」と出す。  
仮の勤務は名前の横の「仮」だけで示す。

スマートフォンのリストは、その日の連絡事項がある人、希望がある人、希望外で割り当て済みの人、未提出の人の順に並べる。  
同じまとまりの中は日付を選んだ時点の並びを保つ。

操作はパターン選択の日別と同じである。

| 表示 | 空きのセル、「希望」のセル | 割り当て済みのピル |
|---|---|---|
| 「シンプル」、ポジションが1つ以下の店舗 | 押すと「○」が入る | 押すと外れる |
| 「くわしく」（ポジションが2つ以上） | 押すと、最後に選んだポジションで入る | 押すと、PCはその場のメニュー、スマートフォンは画面中央のモーダルを開く |

メニューとモーダルには、ポジションの一覧（今のポジションにチェック）と「削除」を出す。  モーダルはスタッフ名の下に日付を出す。  
1人の1日に持てるポジションは1つである。  
最後に選んだポジションは、時間指定のPC、パターン選択と同じ場所へ、店舗ごとに端末に覚える。  
「くわしく」の編集中はPCの週の見出しの右に、押せないポジションの凡例と「必要人数設定」を出す。

「くわしく」表示ではポジションごとの「配置/必要」を出す。  色の決まりはパターン選択の日別と同じである。  スタッフ向けの確定シフトには出さない。  
PCは日付と曜日の下に、色の丸と分数を、店舗のポジションの順で縦に並べる。  出すポジションは週でそろえ、分数の下にその日のテンプレートの名前を小さく置く。  合計と「＋1」「▲1」の表記は出さない。  
スマートフォンは日付の見出しの下に「充足 60%　● 販売 2/3　● 製造 1/2」の形の行を常に出す。  開閉はなく、入りきらない分は折り返す。  
「シンプル」表示と、スタッフ向けの確定シフトでは、「3人」の形で人数だけを出す。  PCは日付の見出し、スマートフォンは日付の見出しの横に出す。

充足率は次の式で求め、小数を切り捨てる。  100%未満を赤、100%を緑の文字にする。

```text
充足率 = Σ min(配置, 必要) ÷ Σ 必要
```

対象は必要人数のある「日×ポジション」のすべてである。  多い分は足さない。  
PCは週の見出しの期間の横に、表示中の週の営業日をまとめた充足率を出す。  スマートフォンの充足の行はその日の充足率である。  
必要人数が1つもない週は、週の充足率を出さない。  必要人数のない日はスマートフォンの充足の行を出さず、日付の見出しの横に人数を出す。

### 自動作成

「くわしく」表示で、未確定の募集を編集できるときは、募集期間の勤務をまとめて作る「自動作成」を出す。  PCは上の行の先頭（「下書き保存」の左）に、スマートフォンは上の行の保存と確定のメニューの先頭に置く。  
押すと、「希望シフトから自動で作成する」と「AIで作成する」から選ぶダイアログを開く。  どちらも、希望、必要人数、過去シフト、メモをもとに作り、現在の下書きに上書きする。  希望シフトから作るほうは使用制限がなく、AIは使える回数に制限がある。  ダイアログには、AIを使うときの個人情報の扱いを案内するリンクを置く。  リンク先のヘルプはまだない。  
「作成する」を押したあとに勤務を作る処理は、まだない。  いまはダイアログを閉じるだけである。

### 人数と過不足

人数は、いま在籍していてシフト表に載っているスタッフだけを数える。

| 募集方式 | 数え方 |
|---|---|
| 時間指定 | 人数が変わる時刻で区切る。区切る時刻は、必要人数が変わる時刻と、勤務、休憩の開始と終了である。休憩中の人は数えない |
| パターン選択 | 勤務パターンごと |
| 日付選択 | 1日ごと |

時間指定のPCの日別表示は、表の下に固定した帯で示す。  ポジションごとに1行で、時間の軸にそろえる。  
時間指定のスマートフォンは、日付の見出しの下の「充足」で示す（次の節）。  
パターン選択は、PCでは勤務パターンの見出し、スマートフォンでは「充足」の欄で示す（「パターン選択の日別」の節）。  
日付選択は、PCでは日付の見出し、スマートフォンでは日付の見出しの下の充足の行で示す（「日付選択の表」の節）。

PCの帯には過不足だけを出す。  人数と必要人数は、区間を押して開く欄に出す。

| 状態 | 時間指定のPCの帯 |
|---|---|
| 足りない | 赤の薄い地と実線の枠、「−1」 |
| 多い | 青の薄い地と実線の枠、「+1」 |
| ちょうど | 緑の薄い地と実線の枠にチェックの印。見習いだけの区間は、注意のアイコンも添える |
| 未設定 | 灰色の枠の箱に人数。その日に必要人数が1つもない日は、その行のポジションの色の箱に人数 |

ポジションの色は行の先頭の丸だけに使い、過不足の色と混ぜない。  
PCの帯の見出しは、左の列にその日のテンプレートのメニュー、右に表の上と同じ時刻を置き、区間の数を出さない。  メニューは左の列の幅いっぱいに広げ、入りきらない名前は「…」で省略する。  メニューの右のボタン（「必要人数で表示」）を押すと、帯を必要人数の見せ方へ切り替える。  ボタンの見た目は変えず、中のアイコンを、次に切り替わる見せ方のもの（必要人数は人、過不足は±）へ変える。  必要人数の見せ方では、「必要人数設定」のテンプレートと同じく、必要人数が変わる時刻だけで区切り、ポジションの色を人数に合わせて濃くして「2人」のように出す。  もう一度押すと過不足の見せ方へ戻る。  必要人数がない日は、ボタンを押せない。  帯の各行には、表の行と同じ縦線を区間の後ろに引く。  足りない時間と見習いだけの時間は、帯の区間で示す。  
ポジションを分けていない店舗で必要人数がない日は、帯の行の名前を「全体」ではなく「時間帯人数」にする。  
PCの帯では、その日に必要人数が1つもない（テンプレートが未設定の）日は、人数を実線の枠の箱に入れて出す。  箱の色は、その行のポジションの色（行の先頭の丸と同じ色）にする。  必要人数のある日に必要人数を入れていないポジションは、白の地に灰色の枠の箱に人数を出す。  
ポジションが4つ以上ある日は、過不足か見習いだけの時間のあるポジションだけを出し、残りを1行にまとめる。

人数を1つも入れていないポジションと、必要人数がない日は、未設定として過不足を出さない。  
あるポジションに入っている人が全員、そのポジションで見習いの区間には、注意のアイコンを出す。  PCの帯は、区間を押して開く欄に「スキル見習いのみ」と出す。  区間を押して開く欄には、ほかに「1/3人 担当」の形で、担当する人数と必要人数だけを出し、過不足の文は出さない。  時間指定のスマートフォンの充足には出さない。  
日付の一覧には人数の過不足を出さない。

時間指定の一覧にある週の「計」は、表示の切り替えにかかわらず、勤務の隙間と休憩を引いた勤務時間の合計である。

### 充足（時間指定のスマートフォン）

時間指定のスマートフォンの「くわしく」表示は、日付の見出しのすぐ下に「充足」を出す。  「くわしく」へ切り替えると、充足が上から下りて現れ、「シンプル」へ戻すと上へ戻って消える。  
その日に必要人数が1つもなければ、充足は出さない。

充足は閉じた状態で始まる。  閉じた状態は「充足 72%」と進捗バーの1行で、一覧をスクロールしても上端に留まる。  
行を押すと開き、ポジションごとの帯と、3時間ごとの時刻（「9」「12」、24時より後は「翌3」）を出す。  開いている間も、閉じているときと同じく、日付の見出しの下に留まる。  
開閉の状態は日付を切り替えても保ち、シフト表を開き直すと閉じた状態に戻る。  
充足を開いている間は、「充足 72%」の行の右、開閉の印の左に「不足｜必要」の切り替えを出す。  「必要」を選ぶと、帯をPCの帯と同じ必要人数の見せ方へ切り替える。  必要人数が変わる時刻だけで区切り、ポジションの色を人数に合わせて濃くして「2人」のように出す。  幅の狭い区間は数字だけにする。  「不足」を選ぶと過不足の見せ方へ戻る。  選んでいる側は白の地に濃い文字で示す。  見せ方は端末に覚えない。

充足率は、全ポジションを合わせた1日の値である。  

```
充足率 = Σ min(人数, 必要人数) × 区間の長さ ÷ Σ 必要人数 × 区間の長さ
```

多い時間で余った人数は足さない。  小数は切り捨てるため、少しでも足りない日は100%にならない。  
100%未満は赤の文字、100%は緑の文字で出す。

帯は、必要人数を入れてあるポジションごとに1本で、区間の幅は時間に比例する。  
帯の範囲は、その日の必要人数の、最初の開始から最後の終了までである。  
帯と3時間ごとの時刻は、スタッフのカードのバーと同じ物差し（店舗の表示する時間）と同じ左右の余白で描き、同じ時刻を上下で同じ位置にそろえる。  時刻は、実際の時刻の位置に中央をそろえる。  
帯の高さは20pxで、角は帯全体で丸め、区間の間は1pxのすき間で分ける。  
人数か必要人数が変わる時刻で区切り、状態と差が同じ隣どうしは1つにつなげる。

| 状態 | 色 | 文字 |
|---|---|---|
| 不足 | 赤。1人と2人は薄い地、3人以上は濃い地 | 足りない人数に「−」を付けて「−2」のように出す（PCの帯と同じ）。幅が28px以上の区間にだけ、11pxの太字で出す。白の文字は3人以上だけ |
| ちょうど | 薄い緑 | なし |
| 多い（必要人数が0の時間に人が入っている場合を含む） | 薄い紫 | なし |
| 必要人数がなく、だれも入っていない | グレー | なし |

帯の区間を押しても何も開かない。  人数と必要人数の数、見習いだけの時間は、スマートフォンの充足には出さない。

### その日の必要人数

その日に当たる必要人数は、次の順で決まる。

1. その日だけの指定（別のテンプレートを当てた日、「テンプレートなし」にした日、その日だけ人数を変えた日）
2. 祝日に使うテンプレート（その日が祝日の表にある場合）
3. 曜日に使うテンプレート

テンプレートの作り方は[必要人数設定](shift-setup.md)、祝日の表の更新は[祝日の表の更新](../manual/national-holidays.md)を参照する。

テンプレートは曜日と祝日の設定から自動で当たる。  
ポジションを追加していない店舗では、確定していない募集のシフト表にテンプレートを出さず、どの日も未設定として扱う。  「必要人数設定」で、ポジションを追加するまで必要人数を扱えないことにそろえている。  
別のテンプレートにしたい日は、テンプレートのメニューから選び直す。  メニューには「テンプレート」の見出しの下にテンプレートの一覧と「テンプレートなし」を出し、区切りの下に「必要人数設定を開く」を出す。  
「テンプレートなし」を選んだ日は、曜日や祝日のテンプレートがあっても必要人数を持たず、メニューのボタンに「テンプレートなし」と出す。  
メニューのボタンには、名前の左に時間帯の横棒のアイコンを出す。  閲覧専用で名前だけを出す場合は、アイコンを出さない。  
時間指定のPCの日別表示では人数の帯の見出し、時間指定のスマートフォンの日別表示では日付の見出しの、日付と表示設定の間、パターン選択の日別表示ではPCもスマートフォンも日付の見出し、日付選択のスマートフォンでは日付の見出し、PCの日付選択では日ごとの見出しの「配置/必要」の下にメニューがある。  
テンプレートを選び直しても、シフト表の保存していない勤務は消えない。

その日だけ人数を変える操作、複数の日へまとめて当てる操作、曜日の設定へ戻す操作は、シフト表に出していない。  
以前にその日だけ人数を変えた日は、その必要人数のまま表示する。

募集を確定すると、その時点の各日の必要人数を保存する。  
確定済みの募集のシフト表は、保存した必要人数を表示し、あとでテンプレートや祝日を変えても変わらない。  
確定済みの募集では、テンプレートを選び直せない。

募集を確定すると、その時点の店舗のポジション（名前、色、並び順、既定かどうか）も募集に保存する。  
確定済みの募集は、シフト表、スタッフ向けの確定シフト、確定通知、出力のすべてで、保存したポジションを使う。  
あとで設定の名前や色を変えても、ポジションを削除しても、確定済みのシフトの表示と必要人数は変わらない。  
確定済みのシフトを直して確定し直しても、保存したポジションは書き直さない。  確定のあとに足したポジションは、その募集では選べない。  
保存したポジションを持たない確定済みの募集（この仕組みより前に確定したもの）は、いまの設定のポジションで表示する。

募集を作ったあとで店舗が希望シフトの集め方の種類を変えた場合、その募集では必要人数を未設定として扱う。  
時間指定で受付時間が変わった場合は、募集の受付時間の内側だけを数える。

### 見習いだけの時間帯

あるポジションに入っている人が全員、そのポジションで見習いの時間帯は、確定の前の確認にも「見習いだけの時間帯」として、日、ポジション、時間帯の単位で表示する。  
表示は「シンプル」と「くわしく」のどちらでも行い、保存と確定は止めない。

「くわしく」表示では、見習いだけの時間帯を、日付の確認事項の件数にも1件ずつ足す。  人数の表示の注意のアイコンで、場所を確かめられるためである。  
時間指定のスマートフォンは、充足の帯に見習いだけの時間を出さないため、日付の件数にも足さない。

### 未提出者の仮の勤務

未確定の募集に未提出者がいて、その店舗に前回確定した募集がある場合は、「くわしく」表示の未提出の帯に「前回の勤務を仮で入れる」を表示する。  
押すと、直近に確定した募集の同じ曜日の勤務を、勤務のない未提出者の日へ、「仮」と表示して入れる。  自動では入れない。  
前回と募集方式が違う場合、定休日、今回の募集にない勤務パターンには入れない。

仮の勤務を保存したあとでスタッフが提出すると、そのスタッフの仮の勤務は表示から外れ、希望を点線の枠で示す。  
画面を開いている間に提出された場合も、保存と確定のときに、提出済みスタッフの仮の勤務をサーバー側で取り除く。

## 日付メモ

スタッフが希望シフトに添えた日付メモを、割当の判断材料として表示する。  
メモは`getShiftBoardDateNotes`で割当データとは別に取得し、下書き保存や未保存変更の判定には含めない。管理者は閲覧だけでき、編集はできない。  
その募集にメモが1件もない場合は、メモ列や欄を表示しない。表示の有無は日付ごとではなく募集単位で決める。

| 画面 | 表示 |
|---|---|
| PC 時間指定・日別 | スタッフ列とタイムラインの間に幅200pxの「連絡事項」列を置き、2行まで表示する |
| パターン選択・日別（PC、スマートフォン） | 列や欄を持たない。メモがある人の名前の横にアイコンを出し、PCはマウスを乗せると、スマートフォンはタップすると本文を出す。表示設定に「連絡事項を表示」を出さない |
| PC 日付選択・週表 | 右端に「連絡事項」列を置き、残りの横幅をすべて使う。表示中の週のメモを、先頭に太字の日付を付けて1件ごとに改行し、全文を並べる。メモがある日は、セルの右上に三角を出す |
| SP 時間指定・日別 | カードの最下段にメモの全文を表示する |
| SP 日付選択・日別 | 名前の下に、吹き出しのアイコンを付けてメモの全文を表示する。表示設定に「連絡事項を表示」を出さない |

PCの日別表示では行の高さを変えない。PC 日付選択の週表だけは、メモの長い人の行をメモに合わせて高くし、省略しない。PCの日別表示で省略したメモはホバーとキーボードfocusで全文を表示する。  
メモ本文にはClarityのマスク属性を付ける。

表示設定で連絡事項を非表示にしたときだけ、メモがあるスタッフの名前の右に連絡事項のアイコンを置く。  
PCの3画面では名前セルの右端に置き、ホバーとキーボードfocusで「連絡事項」の見出しとメモをツールチップに表示する。  
SPの時間指定とパターン選択の日別ではカードの名前の右に置き、タップでツールチップと同じ内容を開く。タッチ操作ではツールチップが開かないため、SPはタップで開閉するPopoverにする。  
日別表示はその日のメモ本文だけを、PC 日付選択の週表は表示中の週のメモを日付つきで出す。

上の各画面の日付見出し（PC 日付選択では週の期間の行）の右端に「表示設定」メニューを置き、「連絡事項を表示」でメモの表示と非表示を切り替える。  
非表示にすると、メモ列、メモ欄、件数、セルの右上の三角を隠す。  
代わりに、非表示にしてもメモに気付けるよう、名前の右にアイコンを出す。  
表示状態は日付や表示モードを切り替えても保つが、保存はしない。  
非表示のままのメモの見落としを防ぐため、画面を開くたびに表示から始める。

## 未提出者と自動催促

編集可能な未確定シフトに未提出者がいる場合は、PCでは未提出人数と氏名、SPでは未提出人数と詳細導線をシフト表の下部に表示する。
自動催促の表示は、募集に保存された予定時刻と送信記録から次のように決める。

| 条件 | 表示 |
|---|---|
| 送信記録がある | `M/D(曜) HH:mmに催促通知を送りました` |
| 送信記録がなく、予定時刻前 | `期限前日17時に再通知します` |
| 送信記録も予定もない | `自動催促の予定はありません` |
| 送信記録がなく、予定時刻を過ぎた | 催促状態を断定せず、未提出人数、氏名、詳細導線だけを表示する |

「送りました」は、少なくとも1件の通知処理を登録した送信記録を示す。
メールやLINEの到着と、全対象への送信完了は保証しない。

## 未保存変更

利用者が編集後に別の画面へ移動しようとすると、「保存して移動」「保存せず移動」を選ぶ確認Dialogを表示する。  アプリ内の戻る操作、メニューや設定画面への移動、ブラウザバックのどれでも同じDialogを使う。
Dialogを閉じた場合は画面に留まる。

serverから届いた提出内容の更新だけでは、未保存変更として扱わない。
タブを閉じる操作とreloadでは、ブラウザ標準の離脱確認を使う。

## validationと確認事項

割当の下書き保存を拒否する違反は、`convex/shiftBoard/validation.ts`の`validateShiftAssignments`で収集する。
フロントエンドは確定Dialogを開く前に同じ純粋関数を実行し、確定操作では検証済みの内容を`saveShiftAssignments`で保存してから`confirmRecruitment`を呼ぶ。

`confirmRecruitment`自身は、募集の存在、終了日、確定または再送の状態と、保存済み割当の休業日だけを再確認する。
共通validation全体を単独で再実行するAPIではないため、直接呼び出した場合の保証を強めるかは[現行コードとの差分調査](../plans/2026-07-23_doc現行コード差分調査.md#4-コードと文書のどちらを直すか決める差分)に残す。

違反がある場合は、一覧、日付の件数badge、該当スタッフの強調を連動させる。
編集で違反を直すと表示も更新する。

希望と割当の食い違いは、確定を拒否しない「確認事項」として表示する。
未提出スタッフへの割当、休み希望の日、希望時間外、希望していない勤務パターン、スタッフの担当外のポジションへの割当を対象とし、同じセルに違反がある場合は拒否理由を優先する。
該当スタッフの名前の右に確認事項のアイコンを置き、PCはホバーとキーボードfocus、SPはタップで理由を開く。

初回の確定Dialogでは、割当の有無にかかわらず未提出のスタッフを、確認事項と同じ形の別の見出しで人数と氏名を示す。  
確定すると希望シフトを提出できなくなることを伝え、氏名は省略せずに全員を表示する。確定は止めない。  
未提出のスタッフに有効な管理者が含まれる場合は、シフト対象から外せることと、ヘルプ「スタッフ・管理者をシフトに表示しない」へのリンクを添える。リンクは別タブで開く。  
確定後の再通知では提出リンクが閉じているため表示しない。

## 保存、確定、再通知

募集条件の編集後は、古い条件で開いている画面から下書きを保存・確定できない。  
変更を知らせて再読み込みを案内し、未保存の割当は引き継がない。これにより募集縮小で削除した割当を、古い画面から再保存することも防ぐ。

募集編集で未提出に戻っても、初回提出時刻と下書き保存時刻は保持する。  
下書き保存前に提出済みだった人が追加日の希望を再提出した場合は、希望として表示し、管理者が割り当てる。再提出を理由に割当を自動で復活させない。

下書き保存は現在の割当を一募集分の全置換で永続化する。  `saveShiftAssignments`は受信したraw割当を先にvalidationし、スタッフとポジションの店舗境界を確認する。  その後に省略デフォルトを実IDへ解決し、時間指定の安全に統合できる完全隣接区間だけを一件で保存する。  overlapや不正時刻を正規化で隠さず拒否する。

routeは最初に募集から店舗を解決してURLの組織と一致することを確認する。  読み込み、保存、確定ではその店舗IDと`expectedOrganizationId`を既存manager APIへ同時に渡し、別組織の店舗、legacy店舗所属、有効管理者ではない操作者、削除済み店舗をserver側で拒否する。

既存DBの分割行は一括migrationしない。  ShiftBoard、確定シフト閲覧、新しい通知はread-time正規化するが、読み込みだけでDBを書き換えない。  管理者が既存募集を再保存した場合だけ、その募集の安全に統合できる割当がDBでも正規形へ収束する。

確定時は、前回の確定通知snapshotと現在の割当を比較し、変更があるスタッフだけを通知対象にする。
休憩だけを変えた場合も変更として扱う。  休憩のない勤務のsnapshotは休憩の導入前と同じ形で比べるため、導入だけを理由に再通知しない。  
確定通知とスタッフ向けの確定シフト表示には、勤務の休憩を添える。  ポジションが2つ以上ある店舗では、ポジション名も添える。
スタッフ向けの確定シフト表示は、ポジションの色と名前の対応を凡例で示す。  人ごとの合計と熟練度は表示しない。
時間指定は、旧のsplit snapshotと新しいcanonical snapshotを、raw signatureの整合性を確認した後に勤務内容で比較する。  分割と統合だけの差は再通知対象にせず、壊れたsignatureは安全側で再通知対象にする。
既存募集にsnapshotがない場合は、導入後の初回再通知だけ全員を対象にする。

同じ内容の確定または再通知は、対象店舗、募集、用途、スタッフ、文面に影響する値から作るsemantic keyへ収束する。
fanoutのcursor、lease、対象上限、再開、provider呼出し前の再確認は[Notification Outbox](notification-outbox.md)を参照する。

## PDF・Excel出力

管理者はPC・SPのシフト表から、出力専用ページを別タブで開く。  
出力ボタンを押した時点の勤務内容を別タブへ渡す。「シンプル」表示で希望から自動反映された勤務と、未保存の編集も含み、保存・確定・通知は行わない。  
フォーム初期化中、日付メモの取得中、保存・確定の処理中は出力を止める。出力ページは共通アプリヘッダーを表示せず、認証と対象店舗・募集の閲覧権限を確認する。

帳票には募集の全期間とShiftFormの対象スタッフを含める。選択中の週・日付やスクロール位置には限定しない。  
スタッフ順はDashboardと同じ保存順序を使い、旧形式では管理者を先にする。過去募集の削除済みスタッフは末尾に含める。  
勤務がないセルは `-` にする。スタッフ0件、順序の欠落・重複、取得上限超過、不正な勤務データでは部分的な帳票を作らない。

出力タブは開いた時点の内容を保持し、その後の元画面やDBの勤務内容の更新に追従しない。  
同じタブでは再読み込み後も24時間以内の受信内容を利用でき、受信完了後は元画面を閉じても出力できる。  
ログアウト、利用者切替、閲覧権限の喪失、期限切れでは保持した内容を破棄する。  
受け渡しや復元に失敗した場合はシフト表からの開き直しを案内し、DBの保存内容へ切り替えない。URLだけを共有して帳票を再現する機能は持たない。

出力ページでは出力する形を「一覧」と「日別」から選ぶ。  
「一覧」はスタッフと日付の表、「日別」は1日ごとの勤務のバーである。  出力ページは「一覧」を選んだ状態で開く。  
時刻を持たない日付選択の募集には「日別」がなく、切り替えを出さない。  
Excelは「一覧」だけを出力する。  「日別」を選んでいる間は、Excelのボタンを出さない。  
出力ページの上の段には形の切り替えとダウンロードのボタンを置く。  下の段には選んだ形で使える項目のチェックだけを出す。  
「日別」の内容はこの節の最後の「日別のバー」に書く。  そこまでの説明は「一覧」の内容である。

| 募集方式 | 帳票の表示 |
|---|---|
| 日付選択 | 出勤日に `○`、非出勤日に `-` |
| 時間指定 | 勤務区間ごとに開始・終了を2行で表示し、中抜けを保持する。隣接・重複区間はまとめる |
| パターン選択 | 募集時点の設定順にパターン名を表示し、複数パターンに合わせて行高をそろえる |

定休日列は薄いグレーと `-` で表示する。  
プレビュー、PDF、Excelの見出しは、同一年なら `yyyy/mm/dd~mm/dd 店舗名`、年をまたぐなら `yyyy/mm/dd~yyyy/mm/dd 店舗名` の順で統一する。  
既定ではA4横に全期間を最大31日まで収め、スタッフ方向へ改ページする。  
15日以上のシフトでは、すべての募集方式で「期間を前半・後半に分ける」を選べる。期間をほぼ半分に分け、奇数日数の端数は前半へ含める。  
チェックの切替はプレビューと出力へ即時反映し、PDFは前半の全スタッフ分を出力してから後半へ進む。各期間の先頭に対象期間と店舗名を表示し、ページ番号はファイル全体で通しにする。  
Excelは正式名称を文字列セルに保持し、見出し・スタッフ列の固定と横1ページの印刷設定を持つ。期間を分ける場合は、前半・後半の順に2シートへ出力する。  
長いパターン名はExcelでは折り返し、全スタッフ行に必要な高さを確保する。PDFとプレビューは縮小・末尾省略で行数を固定する。  
Excel上の変更をシフトリへ取り込む機能は持たない。

出力ページ、PDF、Excelには下書き・確定済みなどの状態ラベルや通知状況を表示しない。  

一覧には、勤務の開始と終了（日付選択は `○`、パターン選択はパターン名）だけを出す。  
ポジション、休憩、人数、過不足、合計、熟練度は出力しない。  ポジションの違う隣り合う勤務は、1つの勤務にまとめる。  
ポジションと休憩は「日別」で出す。  Excelは一覧だけを出力するため、Excelにもポジションと休憩は入らない。

日付メモは、出力ボタンを押した時点の内容を勤務内容と一緒に出力タブへ渡し、同じ条件で保持・破棄する。  
メモがある募集だけ「連絡事項も出力する」を表示し、初期状態はオフにする。シフト表本体にはメモを入れない。  
オンにすると、PDFはシフト表の後ろの新しいページ、Excelは「連絡事項」シートに、日付・名前・内容を日付順、同じ日はスタッフ順で出力する。PDFのページ番号は連絡事項を含めて通しにする。メモ本文はExcelの文字列セルとして書く。  

ファイルはブラウザ内で生成する。  
分割設定の変更、権限失効、ページ離脱で古い生成結果を破棄し、失敗時は再試行できる。  
スマートフォン実機の保存操作と物理印刷の確認状況は、実装・自動テストの保証範囲と分ける。

### 日別のバー

「日別」は時間指定とパターン選択の募集で、1日を1ページ（A4横）にしたPDFを出力する。  
期間のすべての日を1つのPDFにまとめる。  定休日と、勤務が1人もいない日のページは作らない。  
ファイル名には一覧と区別するために「日別」を入れる。

| 項目 | 内容 |
|---|---|
| 見出し | 日付、曜日、店舗名。右に「出勤 5人」のように、その日に勤務のある人数を出す。人数の行と同じく、削除済みのスタッフは数えない |
| 載せる人 | その日に勤務のある人だけ。開始の早い順、同じなら終了の早い順、それも同じならスタッフの表示順に並べる。削除済みのスタッフは、名前に「（削除済み）」を付けて載せる |
| 行の内容 | 名前、その日の最初の開始と最後の終了、時刻の軸にそろえた勤務のバー |
| バー | ポジションの色を白で薄めた色で塗り、文字を黒にする。ポジションが2つ以上ある店舗では、バーの中にポジション名を書く。パターン選択では、パターン名も書く。色を持たない勤務は灰色にする |
| 休憩 | 斜線で示し、中央に「休」と書く。1文字が入らない狭い休憩には書かない。休憩として扱う範囲は、シフト表と同じ（勤務の開始より後、終了より前）である |
| 時刻の軸 | 期間を通して同じ範囲にする。募集の時間帯（パターン選択は、最も早い開始から最も遅い終了まで）を正時にそろえ、その外に勤務がある場合は広げる |
| 空行 | 勤務のある人のあとを、ページの下まで空行で埋める。急な交代を手で書き込むためである |
| 人数 | ページの下に、時間ごとの人数を、人数が変わる時刻で区切って出す。必要人数、過不足、充足率は出さない |

ポジションと休憩は、日別だけに出す。  
バーの色を薄めるのは、バーの中の文字を読みやすくするためである。  画面と同じ濃い色に白い文字を載せると、紙では文字が薄く見える。  
白黒で印刷しても見分けられるよう、ポジションは色だけでなく名前でも示し、バーを黒の枠で囲む。

人数は、ポジションが2つ以上ある店舗では、その日に勤務のあるポジションごとに1行で出す。  
それ以外の店舗は「時間帯人数」の1行にする。  
休憩中の人と、削除済みのスタッフは数えない。  
0はその行で最初に人がいる時間と最後に人がいる時間の間にだけ書く。  
ポジションが9つ以上ある日と、設定にないポジションの勤務が残っている日は、「時間帯人数」の1行にまとめる。  
パターン選択でも時刻で区切って数える。  シフト表の勤務パターンごとの人数とは数え方が違う。

1ページに収まらない日は次のページへ続け、見出しに「（1/2）」のように何ページ目かを書く。  出勤の人数と人数の行は、その日のすべてのページに、その日全体の値で出す。  
連絡事項は一覧と同じく、選んだときだけ最後のページに付ける。  
勤務が1つもない募集で「日別」を選ぶと、プレビューに「勤務が入っている日がありません」と出し、PDFのボタンを押せなくする。

## Public API

| API | 用途 |
|---|---|
| `api.shiftBoard.queries.getShiftBoardShopScopeForOrganization` | URLの組織、募集、店舗の一致をcanonicalな組織所属で検証し、既存シフト表APIと画面文脈へ渡す店舗ID・店舗名を返す |
| `api.shiftBoard.queries.getShiftBoardData` | 募集、スタッフ、提出、割当をシフト表向けに返す。削除済み募集は`null`を返す |
| `api.shiftBoard.queries.getShiftBoardDateNotes` | 同じ店舗の管理者に、シフト表の有効スタッフの募集期間内の日付メモを`{ staffId, date, note }`だけで返す。削除済み募集と別組織は`null`を返す |
| `api.shiftBoard.queries.getShiftBoardStaffing` | 「くわしく」表示に使う、日ごとの解決済みの必要人数とその理由、当てられるテンプレート、休憩の決まり、スタッフのポジション別の熟練度、前回確定した募集の有無を返す。確定済みの募集は確定時に保存した必要人数を返す |
| `api.shiftSetup.mutations.applyDayTemplateToDates` | 未確定の募集の期間内の日付へ、テンプレートをまとめて当てる。`null`でその日だけの指定を消す |
| `api.shiftSetup.mutations.saveDayCustomRequirements` | 未確定の募集の1日に、その日だけの必要人数を保存する。シフト表の画面からは呼ばない |
| `api.shiftBoard.queries.getProvisionalAssignments` | 未提出者の仮の勤務の候補として、前回確定した募集の同じ曜日の勤務を返す。保存はしない |
| `api.shiftBoard.mutations.saveShiftAssignments` | 割当を検証して下書き保存する |
| `api.shiftBoard.mutations.switchShiftDetailMode` | 「シンプル / くわしく」を切り替える。その募集の下書きの勤務と下書き保存の時刻を削除し、選んだ表示を店舗に保存する。確定済みの募集では拒否する |
| `api.shiftBoard.mutations.confirmRecruitment` | 保存済み割当の休業日を再確認して確定し、必要な確定通知を予約する。未確定から確定へ変わるときに、各日の必要人数を保存する |
