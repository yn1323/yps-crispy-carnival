# 分析KPI蓄積基盤

店舗登録、希望シフトの提出、シフト確定を、操作が成功したJST日ごとに記録する分析基盤です。  
最初の対象操作、またはJST 03:00の定期処理で計測を開始します。開始前のbackfill、reset、集計用環境変数の切替は不要です。

実装と実環境への反映は別です。公開状況は[リリース状態](../manual/release-status.md)、反映後の運用は[Analytics運用](../manual/analytics-rollout.md)を参照してください。

## 日次指標

| 指標 | 記録する操作 |
|---|---|
| 新規登録店舗 | 初期店舗または追加店舗の作成 |
| 提出があった店舗 | 有効な希望シフトの保存。再提出と全休みを含む |
| 確定した店舗 | 初回確定または変更後の再確定 |

同じ店舗・同じ日の繰り返しは1店舗です。翌日に操作すれば翌日の実績になります。  
失敗した操作、下書き保存、通知だけの再送、変更のない確定の再実行は数えません。既存店舗を開始日に新規登録として数えません。

日付はサーバーの受理時刻から決めます。募集開始日や現在の更新日時から過去の活動を推定しません。  
業務変更と同じtransactionで記録するため、記録に失敗すれば業務変更もrollbackします。後日店舗や募集が削除されても、記録済みの実績は減らしません。

7日・30日・90日の期間値も店舗ごとに重複を除きます。日別の件数を足し合わせません。

## 保存するデータ

| table | 役割 |
|---|---|
| `analyticsState` | 計測開始日時、定義version、未集計日を確認する位置 |
| `analyticsShopDays` | 店舗・日ごとの登録、提出、確定の有無 |
| `analyticsCycleEvidence` | 問い合わせで参照する、計測開始後の提出・確定日時 |
| `analyticsDailyResults` | 日別と固定期間の店舗数、集計状態、再試行と進捗 |

氏名、メールアドレス、LINE user ID、提出内容、通知本文、要望本文はAnalytics tableへ複製しません。  
現在の店舗やスタッフは[問い合わせ用API](analytics-dashboard.md)から読み、日次集計の有無に依存させません。

## 自動集計と復旧

JST 03:00に前日分を集計します。最初の起動でまだ計測開始前だった前日を0件として作りません。  
初日は開始時刻以降だけを観測し、画面で「初日は途中から計測」と明示します。翌日から完全な一日分になります。

集計は店舗を有界pageで読み、日別と7日・30日・90日の件数を同じrunへ保存します。  
進捗versionと次pageの予約を同じtransactionで更新し、遅れて届いた旧pageや重複実行を拒否します。成功時だけ数値を公開します。

失敗時は1分・5分・15分後に再試行します。翌日の定期処理も、失敗・長時間停止したrunと未作成日を確認します。  
復旧対象は計測開始後の保存済み事実だけです。開始前の履歴を作るbackfillではありません。失敗を0件に置き換えず、成功した他の日は閲覧できます。

| 状態 | 公開する内容 |
|---|---|
| 開始前 | 計測開始前。数値なし |
| 初日の集計成功 | 観測開始時刻を伴う部分日の数値 |
| 完全日の集計成功 | 実績なしなら0店舗 |
| 未集計・実行中・失敗 | 状態を表示。途中の数値は非公開 |
| 期間に未集計・失敗日あり | 日別の成功値は表示し、期間値は未確定 |

## 保持期間

店舗の日別事実と募集の観測記録は25か月、店舗IDを残さない集計結果は5年保持します。  
週次処理が期限切れデータを有界pageで削除します。再試行に必要な入力が保持期限を過ぎたrunは復旧不能として確定し、保持期間を無期限に延ばしません。

旧scheduled callの受け口は無処理で終了させ、廃止済みtableへアクセスしません。旧Analytics tableのデータ移行は、既存データがないという今回の前提に従って実装しません。
