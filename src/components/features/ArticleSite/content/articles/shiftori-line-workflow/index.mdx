# LINEのシフト希望をあとから探さないために

深夜に届く「やっぱり明日休みでお願いします」。
翌朝、担当者はどの希望が最新なのか確かめるためにトークをさかのぼり、Excelへ書き写します。

LINEは連絡に便利なのに、シフト希望を集め始めると「探す、確かめる」が毎月増えていきます。
手間を生んでいるのは、連絡手段そのものなのでしょうか。

## LINEで集めると確認が増える理由

LINEのトークは、スタッフとの連絡を時系列で読む場所です。
希望を人ごとに並べたり、提出状況を一覧にしたりする役割は持っていません。

たとえば、締切までの数日だけでも次の連絡が重なります。

- 締切後に「やっぱり入れません」が個別トークで届く
- グループと個別のどちらで希望を受けたか分からなくなる
- 最新の希望を見つけるために上へスクロールする
- Excelに写したつもりでも、1人分が抜けている

一つずつは短い作業です。
しかし、10人分を毎月繰り返すと、希望を集める作業に加えて、希望を探して確かめる時間が積み重なります。

担当者の段取りだけでは、この作業を減らしにくい状態です。
希望がグループと個別のトークへ分かれ、一覧で確認できないことが原因だからです。

---

## 提出場所を一つにすると何が変わるか

LINEでの連絡は残したまま、回答先を一つの入力フォームに固定します。
スタッフは自由返信ではなく、毎回同じ場所へ希望を入力します。

提出場所が一つになると、締切後の確認方法が変わります。

| いままで | 提出を一か所にまとめると |
| --- | --- |
| トークをさかのぼって最新を探す | 提出一覧を上から見る |
| 誰が出したか指折り確認する | 届いた回答を一覧で確かめる |
| LINEから手で転記する | 入力された希望をそのまま見る |

特別なツールがなくても、「希望はこのフォームに」と決めれば、探す場所を減らせます。
入力フォームだけでは、未提出者を特定するための名簿との照合は残ります。

[シフトリ](https://shiftori.app)では、提出済みか未提出かもスタッフごとに確認できます。

ただし、希望を一か所に集めても、調整と共有を別の場所で扱えば確認先は再び増えます。
提出された希望を調整し、確定したシフトを共有するところまでを同じ流れで扱えば、確認先を増やさずに済みます。

## 回収した希望が確定シフトになるまで

### 1. 希望を集める

シフト期間と締切を決めて、募集を作ります。
スタッフごとに提出リンクが発行され、連携状態に応じてLINEまたはメールで送られます。
スタッフは届いたリンクを開き、入れる日や時間を入力します。

新しいアプリを入れてもらう必要はありません。
スタッフ側の操作は、リンクを開いて入力するところまでです。

### 2. 集まった希望を見ながら調整する

提出された希望は、シフト表の画面でまとめて見られます。
時間を伸ばす、短くする、別の日に動かすといった調整を、希望と確定予定を同じ画面で見比べながら進められます。

締切までに提出したスタッフの画面には、締切後に「提出内容をもとに、お店でシフトを調整しています」と表示されます。
スタッフも自分の希望がどの段階にあるかを確認できます。

### 3. 確定したシフトを共有する

シフトが決まったら確定し、スタッフへ閲覧リンクを送ります。
LINE連携済みのスタッフには通常LINEで送り、LINEを利用できない場合や送信上限に達した場合はメールへ切り替わります。
連絡手段が混ざっているお店でも、同じ管理画面から扱えます。

確定から共有までを同じ流れで進めるため、「シフト表はできたが、まだ送っていなかった」という共有漏れも起きにくくなります。

---

## 次のシフト募集で比べる確認の手間

最初からすべての運用を変える必要はありません。
まずは次のシフト募集一回分だけ、回収から共有までを同じ流れで試してみてください。

翌朝にトークをさかのぼった回数と、Excelへ転記した回数を振り返れば、今のやり方との違いを具体的に比べられます。
最新の希望を見る場所が一つに決まっていれば、深夜に変更連絡が届いても確認先を探し回らずに済みます。
