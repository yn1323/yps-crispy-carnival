# LPに埋め込む製品紹介動画

LPで流す製品紹介動画（機能、アピールポイント、利用者にとってどう嬉しいか）を作るときの判断基準である。  
Remotionのコードの書き方は[Remotion Markup Best Practices](../remotion-markup/REFERENCE.md)、画面内の配置と文字サイズの下限は[Video Layout Rules](../remotion-create/video-layout.md)に従う。  
広告配信用の動画には使わない。

数値は2026年9月時点の調査に基づく目安である。  
数値が判断を左右する場合は、末尾の参考から現在の一次情報を確認する。

## 1. 最初に型を決める

markupを書く前に、置き場所、見る人、見た後の行動を決める。  
決まっていなければユーザーに確認する。

| 型 | 置き場所 | 再生 | 音 | 尺の目安 |
|---|---|---|---|---|
| ヒーローループ | ファーストビューの製品ビジュアル | 自動、ミュート、ループ | なし | 10〜20秒 |
| 機能ループ | 各機能セクションの静止画の置き換え | 画面に入ったら自動、ミュート、ループ | なし | 5〜15秒 |
| 説明動画 | ファーストビューの直下、または専用セクション | クリック再生。音声がなければ画面に入ったら自動再生してよい | ナレーション、BGM、字幕。音声なしで字幕だけでもよい | 60〜90秒 |

- 音のある動画を自動再生しない。ブラウザは音声付きの自動再生を止め、訪問者にも押し付けに感じられる。
- ナレーションで説明する動画はクリック再生にする。音声のない説明動画は、画面に入ったら音なしで自動再生してよい（8章）。
- 1分を超えると離脱が増える。完走率は1分未満で約66%、1〜2分で約56%である（Vidyard）。
- 説明動画を長くしない。4分のデモを90秒へ縮めてコンバージョンが上がった事例がある。

## 2. 機能ではなく「どう嬉しいか」を見せる

- 各シーンを「利用者の困りごと → 製品での操作 → 結果として楽になること」の順に組む。
- 見出しテロップには機能名ではなく結果を書く。例として「自動リマインド」より「『シフトまだ？』と聞いて回らなくてよくなる」を選ぶ。
- 1シーンで伝えることは1つにする。説明動画でも見せる機能は3つまでにする。
- 冒頭はタイトル画面（ロゴと「紹介動画」などの動画の名前）にし、いきなり本編の場面から始めない。0フレーム目は再生前のサムネイルにもなる。
- タイトルの次の5秒以内に、いちばん伝えたい価値を出す。
- 説明動画は「今のやり方の手間 → 製品画面での解決 → Before/Afterの結果 → 次の行動」の順に組む。
- 動画はLP本文の読み上げにしない。静止画では伝わらない変化（届く、集まる、そろう、切り替わる）を見せる役割を持たせる。
- 動画の言葉とLP本文の言葉をそろえる。同じ機能を別の名前で呼ばない。
- 利用者が複数いる製品は、それぞれの立場で嬉しい場面を分けて見せる。
- 効果の数値（「作業時間が半分」など）は、根拠を示せるものだけを使う。
- 字幕には画面で起きていることを書く。「書き写す手間がなくなる」のように、見る人が意味を補わないと分からない言い方や、それを表すための小道具を足さない。
- 動画の中にボタンを置かない。押せないうえ、LPのボタンと重なる。締めは「2か月無料でお試しできます」のように、始める条件を具体的に書く（6章）。

## 3. 製品画面の見せ方

- 実画面の録画ではなく、Reactで再構成した簡略UIを基本にする。不要な要素を消せて、UI変更に強く、どの解像度でも鮮明に描ける。
- 本物らしさが必要な場面だけ、実際のスクリーンショットを`staticFile()`で使う。
- ナビゲーション、設定、細かい補足など、その場面の話に不要な要素は描かない。
- 操作している部分へズームして見せる。画面全体から詳細へ寄るか、カメラを固定してUIを拡大するかを1本の中で統一する。
- 読み込み中の表示や待ち時間は見せず、操作の直後に結果を出す。
- 実際の製品にない動作を見せない。手動の操作を自動のように見せない。
- 製品の画面や通知の文言をそのまま映す前に、日本語として自然か確かめる。不自然なものは動画側で自然な言い方にする。
- イラストは写真より優先し、[illustrations.md](illustrations.md)の手順でCodexに作らせる。1本の動画の中ではタッチをそろえる。
- カーソルは直線で動かさず、ゆるやかな曲線で減速させる。クリック時は縮小や波紋で押したことを示し、止まっている間は消す。
- スマホで使う人の画面とPCで使う人の画面を、端末の枠で描き分ける。
- UI内の文字も、LP上で読める大きさまで拡大する（5章）。
- データはダミーにする。空の状態や極端な値を避け、現実的な件数と名前を使う。
- LPの静止画と色、角丸、余白をそろえる。

## 4. 音なしで伝わる文字

自動再生はミュートなので、音なしで伝わることを前提にする。  
説明動画にも字幕を入れる。

- 字幕の句読点は、[シフトリUI文言の「日本語の構造」](../../ui-architect/references/ui-writing.md)に従う。
- 要点を示すバッジや見出しは、画面を大きく使って見せる。場面転換のために、要点の文字を小さく縮めた状態で見せない。
- 表示時間は「文字数 ÷ 4」秒以上にする。初見の人は作り手より読むのが遅いため、余裕を持たせる。
- 横長の画面では1行13〜16文字、2行までにする。スマホ幅で表示される動画は1行8〜10文字にする。
- ループ動画は途中から見られる。各シーンが単独で意味が通るようにし、最終フレームを最初のフレームへ自然につなげる。
- ナレーションと画面の文字は同じ内容にする。文字と音声が一致すると内容が認識されやすい。
- 字幕は音声より1〜4フレーム先に出し、話し終わりの一拍後に消す。
- ゴシック体のMedium以上を使い、背景とのコントラスト比を4.5:1以上にする。書体は2種類まで、強調色は1〜2色までにする。
- 動画の中で点滅を使う場合は、1秒に3回を超えない。

## 5. LP上の表示サイズで確認する

LPでは動画が縮小されて表示されるため、書き出し解像度ではなく実際の表示幅で文字の大きさを判断する。

- 画面上の文字の大きさは「動画内の文字サイズ × LP上の表示幅 ÷ compositionの幅」になる。
- この値が本文で16px前後、見出しでそれ以上になるように、テロップとUI内の文字の大きさを決める。
- 1920px幅の動画を640px幅で表示すると、動画内の48pxは16pxになる。
- `remotion still`で書き出した画像をLP上の表示幅に縮小して、読めるか確認する。

## 6. 条件付きの訴求（景品表示法）

「無料」「〇か月無料」「クレジットカード登録不要」「〇名まで無料」のように条件がある訴求を動画に入れる場合は、条件（打消し表示）を次のように出す。

- 強調した表示と同じ画面の、すぐ隣に出す。別の画面に分けない。
- 強調した表示と釣り合う大きさで、背景と区別できる色で出す。
- 強調した表示と条件の両方を読み終えられる時間だけ、画面を表示する。
- 強調した内容をナレーションで言う場合は、条件もナレーションで言う。
- 条件を出す画面に、視線を奪う画像や動きを置かない。
- 1本の中に、条件付きの訴求を何種類も入れない。

料金とプランの数値は変わりやすく、動画に焼き込むと更新が遅れる。  
料金の説明はLP本文に任せ、動画には入れないことを優先する。  
締めで無料を伝える場合は、「2か月無料でお試しできます」のように条件（期間）を同じ文に含める。

## 7. 音（説明動画）

- ナレーションは1分250〜300字を目安にし、話の区切りに間を入れる。
- BGMはナレーション中に18〜20dBほど下げる。
- 全体のラウドネスは統合で−14 LUFS前後、トゥルーピークは−1 dBTP以下を目安にする。
- 操作に合わせた効果音は[sfx.md](../remotion-markup/sfx.md)を使う。
- ループ動画には音声トラックを入れない。

## 8. LPへの埋め込み

- ループ動画は`autoplay muted loop playsinline`を付けた`<video>`にし、WebMを先、MP4を後に指定する。iOSでは`playsinline`がないと自動再生されない。
- `poster`には動画の実フレームを使う。0フレーム目を、止まっていても意味が通る絵にしておく。
- ファーストビュー外のループは`preload="none"`にし、画面に入ってから再生する。
- 説明動画はページ内に埋め込み、`controls`、`preload="none"`、内容が分かる`poster`を付ける。ポップアップにはしない。
- 音声のない説明動画を自動再生する場合は、画面に半分以上入ったら音なしで再生し、半分未満になったら一時停止する。利用者が止めた後と、最後まで再生した後は、画面に入り直しても再開しない。ループはしない。
- スマホ向けに720pの軽い版を作り、`<source media="(max-width: 767px)">`を先に、PC向けを後に置いて出し分ける。
- すぐ近くに同じCTAや料金の表示があるなら、動画の下に重ねて置かない。
- ループ動画の容量は、デスクトップで4MB、モバイルで2MB以下を目安にする。720pを基本にし、それ以上は容量が収まる場合だけにする。
- 自動再生で5秒を超えて動き、ほかの内容と並んで表示される場合は、一時停止の手段を付ける（WCAG 2.2.2）。
- OSで動きを減らす設定（`prefers-reduced-motion`）が有効な場合は、自動再生せず`poster`を表示する。
- 音声のある説明動画には字幕を付ける（WCAG 1.2.2）。
- 音声のない動画には、同じ内容を伝える説明文を用意する（WCAG 1.2.1）。`<video>`にはaltがないため、`aria-label`で名前を付け、画面に出さない説明文を`aria-describedby`で結ぶ。
- 見た目の比較テスト（VRT）では動画を再生させず、`poster`のまま撮影する。

## 9. Remotionでの作り方

- 置き場所ごとにcompositionを分ける。説明動画は1920×1080、ループはLP上の枠と同じ縦横比にする。
- シーンは1コンポーネント1ファイルにし、[Multi-scene videos](../remotion-markup/multi-scene-video.md)と[transitions.md](../remotion-markup/transitions.md)で組む。
- 日本語フォントは[google-fonts.md](../remotion-markup/google-fonts.md)の方法で読み込む。OS標準フォントに任せると、書き出す環境で見た目が変わる。
- テキストが枠に収まるかは[measuring-text.md](../remotion-markup/measuring-text.md)で確かめる。
- 字幕は[Remotion Captions](../remotion-captions/REFERENCE.md)、ナレーションは[voiceover.md](../remotion-markup/voiceover.md)に従う。
- ループ動画は`--muted`を付けて書き出す。WebMは`--codec=vp9`、MP4は`--codec=h264`で書き出す。
- `poster`用の画像は`remotion still --frame=0`で書き出し、WebPにする。
- フレームはPNGで書き出す（`Config.setVideoImageFormat("png")`）。平らな色面の多いイラストとUIでは、JPEGのノイズで動画が約2倍に重くなった。
- 描画はソフトウェア描画にする（`Config.setChromiumOpenGlRenderer("swangle")`）。手元のChromeのGPU描画で並行して書き出すと、一部のフレームだけ画面全体に要素が敷き詰められたような絵になり、再生すると一瞬乱れて見えた。
- 書き出した後は、壊れたフレームがないか確かめる。隣り合うフレームのSSIMが前後とも低く、1フレーム飛ばした前後はよく似ているフレームを壊れたものとみなす。単体の`remotion still`では再現しないため、書き出した動画そのものを調べる。
- LP用は、書き出した元動画からffmpegでPC向け（1920×1080、CRF 23）とスマホ向け（1280×720、CRF 25）を作る。音声を外し、`-movflags +faststart`を付ける。
- カメラで寄るときも、画面の中身が字幕帯より下に収まる拡大率と中心にする。字幕の背後には白い帯を敷く。
- 後の時点から始まる動き（popなど）の初期状態を、その時点より前に効かせない。まだ動いていない要素が、縮んだまま、消えたままになる。
- opacityやscaleを複数の動きで使う場合は、上書きせず掛け合わせる。
- シーンの始まりの状態を、前のシーンの終わりの状態と一致させる。数値、選択状態、カーソルの位置が飛ばないようにする。
- 確認は、バンドルを一度作り、`remotion still <バンドル> <composition> <出力> --frame=<n>`で主要フレームを書き出して、一覧画像で見る。書き出した動画は、シーンのつなぎ目の前後のフレームを取り出して見る。
- 描画用のChromeを別途ダウンロードしない場合は、`--browser-executable`で手元のChromeを指定する。

## 10. 仕上げ前の確認

- [ ] 音なしで要点が伝わる
- [ ] 最初の5秒に価値と製品名がある
- [ ] 各シーンの見出しが機能名ではなく結果になっている
- [ ] 0フレーム目がタイトル画面で、止まっていても何の動画か分かる
- [ ] 各テロップが「文字数 ÷ 4」秒以上表示される
- [ ] 短い字幕に、読点で間を取った文がない
- [ ] 見る人が意味を補わないと分からない字幕や小道具がない
- [ ] 動画の中に押せないボタンがない
- [ ] 要点のバッジや見出しが、小さく縮んだまま映っていない
- [ ] シーンのつなぎ目で、要素の状態や位置が飛んでいない
- [ ] 書き出した動画に、1フレームだけ壊れたフレームがない
- [ ] LP上の表示幅で文字が読める
- [ ] ループの継ぎ目が自然につながる
- [ ] 条件付きの訴求は、条件が同じ画面の隣に十分な時間出ている
- [ ] 実在の人や店舗の情報が入っていない
- [ ] ループ動画に音声トラックがなく、容量が目安以内に収まる
- [ ] LPに載せている場合は、PC向けとスマホ向けを作り直して差し替えた

## シフトリで作る場合

- 訴求の軸は、LP本体（`src/components/features/LandingPage/`）の見出しと本文に合わせる。動画のために新しい言い回しを作らない。
- スタッフ（届いたリンクからスマホで提出する人）と、店長やシフト担当者（回収、催促、作成、共有をPCやスマホで進める人）を分けて見せる。
- 通知は受け手の視点で「届きます」と書き、主語のない「送ります」を避ける。
- 動画にはLINEのロゴ、LINEの画面や吹き出しに似せたデザイン、LINEの名前を出さない。名前を載せた動画はLINEヤフーの事前確認が必須になる。届く先は「スタッフのスマホに届く」のように書く。LPの本文では「LINE」と書いてよい。
- アプリの画面や通知の文言には、不自然なものが含まれる。動画に映す前に確かめる。
- LPの動画は`src/components/features/LandingPage/IntroVideoSection/`にあり、元データは`apps/video`で作る。
- 壊れたフレームは`pnpm --filter @shiftori/video check:frames <動画>`で調べる。
- 料金やトライアルの条件を入れる場合は、現在の値を実装と`doc/features/organization-billing.md`で確認し、6章に従う。
- 本体（`src/`）のcomponentは動画からimportせず、見た目を合わせた簡略UIを`apps/video`内に作る。本体の変更で動画の書き出しが壊れないようにするためである。
