# 選ばれたUIの実例

この文書には、ユーザーが選んだUIの形と理由を実例として残す。
言葉の規則にしきれないレイアウトや見た目の好みを、次の案を作るときの判断材料にする。
安定した原則は`doc/rules/ui-design.md`、文言の規則は`ui-writing.md`を正本とし、この文書へ複製しない。

## 使い方

- 案を作る前にこの文書を読み、条件が近い実例があれば、その形と理由を案へ反映する。
- ユーザーが案を選んだとき、または見た目について指摘したときに、実例を1件追加する。
- 実例は条件、選んだ形、理由、基準にする画面の4点で書く。
- 同じ好みが2件以上の実例に現れ、適用範囲と理由を言葉で説明できる場合は、`doc/rules/agent-instructions.md`の「指摘の昇格」に従って正本へ移し、元の実例を削除する。
- 現在の画面と合わなくなった実例は削除する。

## 実例

### ヘッダーやツールバーの直下に枠線付きの要素を置く場合

- 条件: ヘッダーやツールバーの直下に、カードや表など枠線を持つ要素が続く。
- 選んだ形: ヘッダー側の下線を付けない。
- 理由: ヘッダーの下線とコンテンツの枠線が重なり、線が太く見える。
- 基準にする画面: シフトボードのツールバーとガントチャート。

### 既存の画面に、設定した店舗だけが使う情報を足す場合

- 条件: シフト表に、ポジションの色分け、人数と過不足、合計時間、熟練度の印を足す。設定していない店舗と少人数の店舗は、今の画面のまま使いたい。
- 選んだ形: 「シンプル / くわしく」の2段の切り替えを1つ置く。シンプルは今の画面と同じにする。項目ごとのオンオフと、設定した店舗での常時表示は選ばれなかった。
- 理由: 足す情報は画面を見づらくするので、今のシンプルな表示を残したい。切り替える箇所は1つにとどめる。
- 基準にする画面: シフト表（2026-11-16の実装計画）。

### 項目の多い設定を足す場合

- 条件: ポジション、日の型（時間帯ごと・ポジションごとの必要人数）、休憩の決まり、スタッフごとの属性を店舗に設定させる。そのまま並べると入力欄だらけになる。
- 選んだ形: 店舗ごとの専用ページに置き、既存の店舗詳細にはリンクだけを足す。人数は表の各マスを−／＋で増減し、文字の入力欄を型の名前だけにする。スタッフの属性は一覧でまとめて編集する。初期値を入れた状態から、違うところだけを直す。
- 理由: 入力欄を並べる設定は使われない。人数分だけ画面を開く形も避けたい。
- 基準にする画面: シフト作成の設定ページ（2026-11-16の実装計画）。

### PCとスマートフォンで操作を分ける場合

- 条件: 同じ機能をPCとスマートフォンの両方に出す。
- 選んだ形: レイアウトは分けてよい。片方でしかできない操作は作らない。
- 理由: スマートフォンだけでシフトを組む担当者が、PCへ移らずに終えられるようにする。
- 基準にする画面: シフト表（2026-11-16の実装計画）。
